## Stack
- Runtime: Node.js, TypeScript 4.8
- Framework: React 18 (popup), Chrome Extension Manifest V3
- State: Redux Toolkit + Redux Saga
- Build: Webpack 5 (ts-loader)
- Package manager: npm

## File Organization
- Content scripts under `src/contentScript/`
- Popup UI under `src/popup/`
- Redux store in `src/redux/`
- Utilities in `src/utils/`
- Constants in `src/constants/`
- Static assets (manifest.json) in `src/static/`

## Naming Conventions
- Files: camelCase.ts (e.g., `contentScript.ts`, `removeDuplicates.ts`)
- Functions/methods: camelCase (e.g., `calculateMiniumAcceptableOffer`)
- Types/interfaces: PascalCase (e.g., `EquipmentType`, `SqsProducerOptions`)
- React components: PascalCase (e.g., `Popup`)

## Import Style
- Relative paths throughout (`../redux`, `../utils/removeDuplicates`)
- Named imports preferred (`import {store, saveDatLoadsToStore} from "../redux"`)
- No barrel files — direct imports to modules

## Error Handling
- try/catch with console.log/console.error (no typed error classes)
- Sagas catch errors silently to prevent crash

## Chrome Extension Patterns
- Content script injects page-level script via `chrome.runtime.getURL`
- XHR monkey-patching to intercept DAT API responses
- `window.postMessage` for content-script <-> injected-script communication
- `chrome.runtime.onMessage` for popup <-> content-script communication
- `chrome.tabs.sendMessage` for popup -> content-script messages

## State Management
- Redux Toolkit `configureStore` with `combineReducers`
- Redux Saga for side effects (DOM manipulation, deduplication)
- Two slices: `loads` (scraped data) and `loadFilters` (rate config)
- Action types as string literals (`"STORE_DAT_LOADS"`, `"TEST"`, etc.)
