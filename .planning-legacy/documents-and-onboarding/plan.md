# Track 5+6 — Documents & Carrier Onboarding

> Generated by /prd-refine on 2026-04-23

## Problem

**Documents:** The document system works end-to-end but has a legacy field name (`s3Url` should be `url`), the driver portal uses a separate upload component instead of the shared one, and load templates can't attach rate con documents. These are polish and consolidation items that reduce tech debt before MVP staging.

**Carrier Onboarding:** The onboarding gate (`checkCarrierOnboarding`) validates required documents at dispatch time, but there's no way for an admin to override the block, the onboarding completion email never actually sends (TODO in subscriber), and the carrier detail page lacks an expired insurance badge. These gaps break the end-to-end onboarding→dispatch flow for external/leased carriers.

## Solution Overview

Combined plan covering document system cleanup (Track 5) and carrier onboarding completion (Track 6). The two tracks share the document domain — onboarding gates check document types managed by the document system.

## Capabilities

### Must Have (P0)
- Rename `s3Url` → `url` across schema, API, and UI (breaking change, migration)
- Merge driver portal upload into shared `DocumentUpload` component (mobile-configured)
- Block onboarding completion when required docs missing (EXTERNAL/LEASED carriers)
- Admin dispatch override per-load with audit logging
- Onboarding completion email actually sent to org admin
- Insurance expiry badge on carrier detail (expired state)

### Nice to Have (P1)
- Rate con attachment on load templates

## User Flows

### Flow 1: Document Upload (Driver Portal — Mobile)
1. Driver opens portal via SMS deep-link
2. At AT_PICKUP+ status, sees document upload section (using shared DocumentUpload component in mobile config)
3. Selects BOL_SIGNED or POD document type
4. Picks file (camera capture on mobile, file picker on desktop)
5. Upload progress shown → success confirmation
6. `document.confirmed` event fires → invoice readiness re-evaluated

### Flow 2: Carrier Onboarding Gate
1. Carrier completes portal onboarding (company info, equipment, drivers, docs)
2. On session completion attempt, system checks: DISPATCH_AGREEMENT signed? INSURANCE_CERT on file and not expired? W9 uploaded?
3. If missing → session.complete() blocked with specific missing doc list
4. If all present → session completes → `carrier.onboarding.completed` event fires → email sent to org admin with review link

### Flow 3: Dispatch Override (Admin)
1. Dispatcher assigns carrier to load
2. Onboarding gate blocks: "Missing: Certificate of Insurance (expired 2026-03-15)"
3. UI shows "Dispatch anyway" button (admin role only)
4. Admin clicks → modal shows carrier name + missing docs list + required reason textarea
5. Admin enters reason → `POST /carriers/:id/dispatch-override` with `{ loadId, reason }`
6. Override flag set on the load-carrier assignment (per-load, not carrier-wide)
7. AuditLog entry written: action=DISPATCH_OVERRIDE, entityType=LOAD, details include reason + missing docs
8. Load assignment proceeds

### Flow 4: Insurance Expiry Warning
1. Dispatcher views carrier detail page
2. If insurance expires within 30 days: warning badge "Expires in X days"
3. If insurance expires within 7 days: urgent badge "Expires in X days"
4. If insurance expired: error badge "Expired"
5. Badges appear in carrier detail header/overview area

### Flow 5: Rate Con in Load Templates
1. Dispatcher creates a new load → template selector modal opens
2. Templates in `DEMO_TEMPLATES` can have a `rateConDocumentId` field
3. When template selected with rate con, the document is attached to the new load
4. Document appears in the load's DocumentsTab after creation

## Data Requirements

### Schema Changes
- **Document model:** Rename `s3Url` → `url` (Prisma migration + all references)
- **Load model:** Add `onboardingOverride Boolean @default(false)` and `onboardingOverrideReason String?` fields for per-load dispatch override
- **LoadTemplate type (UI only):** Add optional `rateConDocumentId?: string` field

### No New Models
- Override is tracked as fields on Load (not a separate table) + AuditLog entry
- Insurance expiry already exists on Carrier (`insuranceExpiry DateTime?`)

## API/Interface Changes

### New Endpoint
- `POST /api/v1/carriers/:id/dispatch-override` — Admin override for dispatch with missing onboarding docs
  - Auth: ADMIN role only
  - Body: `{ loadId: string, reason: string }`
  - Response: 200 with updated load assignment
  - Side effects: AuditLog entry with action DISPATCH_OVERRIDE

### Modified Endpoints
- All document-returning endpoints: `s3Url` field renamed to `url` in response payloads

### Modified Services
- `carrierOnboardingSubscriber.ts` → `carrier.onboarding.completed` handler: look up org admin email via Membership query, actually call `emailService.sendEmail()`
- `loadService.ts` carrier assignment: respect `onboardingOverride` flag on load

### UI Changes
- `DriverDocumentUpload` component replaced by shared `DocumentUpload` with mobile viewport config
- `LoadTemplate` interface extended with `rateConDocumentId`
- `CreateLoadModal` template selection passes rate con to load creation
- Carrier detail: insurance expiry badge component
- Load assignment: "Dispatch anyway" modal for admin override

## Technical Context

### Existing Code to Reuse
- `DocumentUpload` (`dispatch-ui/features/documents/components/DocumentUpload/`) — shared upload component with presign→upload→confirm flow, already supports all entity types and compliance docs. Needs mobile viewport configuration for driver portal use.
- `checkCarrierOnboarding()` (`dispatch-api/shared/onboardingGate.ts`) — validates 3 doc types for EXTERNAL/LEASED carriers. Returns `{ allowed, missingDocuments }`.
- `carrierOnboardingSubscriber.ts` (`dispatch-api/notifications/services/`) — already subscribes to `carrier.onboarding.completed`, renders email template, just missing recipient lookup + send call.
- `CarrierOnboardingCompleteEmail` (`hussle-emails/src/carrierOnboardingComplete/`) — React Email template already built with `carrierName`, `organizationName`, `reviewUrl` props.
- `AuditLog` model and pattern — used in logout, org switch, role change controllers. Fire-and-forget write.
- `StatusBadge` (`dispatch-ui/components/Statusbadge/`) — colored status indicator, can be extended for insurance states.
- `DEMO_TEMPLATES` (`dispatch-ui/features/load/components/CreateLoadModal/`) — hardcoded template array, `LoadTemplate` interface at `features/load/types.ts:551-558`.

### Key Decisions
- **s3Url rename is a breaking change** — migration renames the column, all API responses and UI references must update atomically. No backwards-compat shim.
- **Per-load override, not per-carrier** — override flag lives on Load, scoped to a single assignment. Next load assignment still checks the gate.
- **Insurance expiry nightly job deferred** — the gate already checks at dispatch time. Proactive warnings are handled by UI badge only. Nightly job is post-MVP.
- **DOCUMENT_UPLOADED notification wiring deferred to Track 11** — the `document.confirmed` event already fires correctly. Customer notification handler is a Track 11 concern.
- **DriverDocumentUpload merged into shared component** — the driver portal's simpler upload component is replaced by the shared `DocumentUpload` configured for mobile viewport (smaller UI, camera-first input).
- **5.BE.2 skipped** — readiness is already derived from Document table queries in `invoiceReadinessSubscriber`. No boolean flags on Load to remove.
