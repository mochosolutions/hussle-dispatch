# Document Management

> Generated by /prd-refine on 2026-04-26

## Problem

Documents already upload end-to-end across all four entities (load, carrier, driver, vehicle), but post-upload they're effectively read-only. A dispatcher today can't preview a doc inline, download it, replace it with a newer version, or delete it. Expiry awareness is also limited — only Track 6's carrier-insurance badge exists.

Beyond management actions, the type coverage per entity is thin. The driver context only allows `LICENSE` + `INSURANCE_CERT`, forcing routine compliance docs (medical card, MVR, drug test, etc.) into the catch-all `OTHER` bucket. Carrier and Vehicle contexts have similar gaps. `OTHER` itself is unlabelled — pick it twice and you get two indistinguishable rows.

## Solution Overview

A single MVP pass that does three things:

1. Adds management actions (View · Download · Replace · Delete · expiry badges) on the shared `DocumentTable` so every entity gets parity automatically.
2. Expands the `DocumentType` enum and per-entity `DOCUMENT_CONTEXTS` mapping with industry-standard doc types so `OTHER` is a true exception, not a daily fallback.
3. Improves `OTHER` UX with a required custom label, and enables it on Load contexts so dispatchers always have an escape hatch.

A right-side `DocumentDetailDrawer`, registered in the existing `drawerRegistry`, provides inline preview (PDF via `<iframe>`, images via `<img>`) plus the action footer. The same Replace flow is reused everywhere by reopening `DocumentUploadDrawer` with `preselectedDocType` + `lockDocType=true`. Delete is admin-only (soft-delete via the existing `archive` endpoint guarded with `requireRole(['ADMIN'])`).

Email-out, drag-out, version-history UI, a global doc library, and notifications/dashboards are explicitly deferred.

## Capabilities

### Must Have (P0)

- Inline preview of any document (PDF + image) in a right-side drawer
- Download document via presigned URL (existing endpoint)
- Replace document — uploads a new file, prior is archived automatically by the existing flow, audit log records the swap
- Soft-delete document (admin only), audit log records the archive
- Expiry badge component reused everywhere a doc with `expiresAt` is shown
- Full per-entity DocumentType coverage so `OTHER` is rare:
  - Driver: 10 new types (MEDICAL_CARD, MVR, DRUG_TEST, ROAD_TEST_CERT, DRIVER_APPLICATION, PSP_REPORT, BACKGROUND_CHECK, ANNUAL_REVIEW, HAZMAT_ENDORSEMENT, TWIC_CARD)
  - Carrier: 5 new types (MC_AUTHORITY, VOIDED_CHECK, NOTICE_OF_ASSIGNMENT, BOC3, IFTA_LICENSE)
  - Vehicle: 6 new types (TITLE, IFTA_DECAL, IRP_CAB_CARD, MAINTENANCE_RECORD, LEASE_AGREEMENT, BIT_INSPECTION)
  - Load: 4 new types (TEMPERATURE_LOG, TONU_DOC, FUEL_RECEIPT, LOAD_PHOTO) + whitelist `BROKER_RATE_CON` and `LOA` on `load-detail`
- `OTHER` accepts a required custom label (max 80 chars), displayed instead of the generic "Other" label
- `OTHER` enabled on `load-detail` and `create-load` contexts (in addition to existing carrier/driver/vehicle)

### Nice to Have (P1)

None for this MVP — anything not P0 is deferred (see Out of Scope).

## User Flows

### Flow 1: Preview a document

1. Dispatcher opens any entity detail page (load/carrier/driver/vehicle) → Documents tab.
2. Clicks a row in `DocumentTable` (or the kebab menu → View).
3. `DocumentDetailDrawer` slides in from the right.
4. The drawer fetches a presigned GET URL via the existing `/documents/:id/download` endpoint.
5. Preview renders inline:
   - `application/pdf` → `<iframe>` (browser-native PDF viewer).
   - `image/*` → `<img>`.
   - Other mime types → "Preview unavailable — use Download".
6. Drawer body shows uploader, upload date, expiry + `ExpiryBadge`, compliance metadata fields.
7. Sticky footer: Download · Replace · Delete (admin only).

### Flow 2: Download a document

1. Row kebab menu → Download (or footer button in detail drawer).
2. Saga fetches presigned GET URL.
3. `window.open(url, '_blank')` triggers download/open in new tab.

### Flow 3: Replace a document

1. Row kebab menu → Replace (or footer button in detail drawer).
2. Detail drawer (if open) closes; `DocumentUploadDrawer` opens with `preselectedDocType` + `lockDocType=true`, prefilled with the row's `entityType` + `entityId` + `type`.
3. Dispatcher uploads a new file. Existing `confirm` flow auto-archives prior docs of the same type for `onePer` types via `documentRepoPrisma.archiveByEntityAndType`.
4. `documentService.confirm` writes an `AuditLog` entry per superseded doc: `action: 'DOCUMENT_REPLACED'`, `metadata: { replacedBy: newDocId, priorS3Key }`.
5. Table refreshes — prior row removed, new row visible.

### Flow 4: Delete (archive) a document

1. Admin clicks row kebab menu → Delete.
2. Confirm dialog ("Delete this document?").
3. On confirm, archive saga calls `PATCH /documents/:id/archive`.
4. API requires ADMIN role; non-admin gets 403.
5. `documentService.archive` writes an `AuditLog` entry: `action: 'DOCUMENT_ARCHIVED'`, `metadata: { fileName, type, entityType, entityId }`.
6. Row removed from table on success (existing list filter excludes archived).

### Flow 5: Upload an OTHER document

1. Dispatcher clicks Upload in any Documents tab → `DocumentUploadDrawer` opens.
2. Picks the `OTHER` card in `DocumentPicker`.
3. Drawer renders a required "Document name" text field (max 80 chars) before the file picker activates.
4. Submit blocked until non-empty.
5. On confirm, `metadata.customLabel` saved on the new Document row.
6. `DocumentTable` Type column renders `metadata.customLabel` instead of generic "Other".

### Flow 6: Expiry badge visibility

1. Any doc with `expiresAt` set renders an `ExpiryBadge` in the table cell and the detail drawer header.
2. Thresholds:
   - `> 30 days` away → no badge.
   - `8–30 days` → warning (yellow) chip "Expires in N days".
   - `1–7 days` → error (red) chip "Expires in N days".
   - `< now` → error (red) chip "Expired".

- **Driver:** `MEDICAL_CARD`, `MVR`, `DRUG_TEST`, `ROAD_TEST_CERT`, `DRIVER_APPLICATION`, `PSP_REPORT`, `BACKGROUND_CHECK`, `ANNUAL_REVIEW`, `HAZMAT_ENDORSEMENT`, `TWIC_CARD`
- **Carrier:** `MC_AUTHORITY`, `VOIDED_CHECK`, `NOTICE_OF_ASSIGNMENT`, `BOC3`, `IFTA_LICENSE`
- **Vehicle:** `TITLE`, `IFTA_DECAL`, `IRP_CAB_CARD`, `MAINTENANCE_RECORD`, `LEASE_AGREEMENT`, `BIT_INSPECTION`
- **Load:** `TEMPERATURE_LOG`, `TONU_DOC`, `FUEL_RECEIPT`, `LOAD_PHOTO`

Existing `Document.metadata` JSON field is reused for `customLabel` on `OTHER` docs — no schema change.

### AuditLog rows (existing model)

- `DOCUMENT_ARCHIVED` — written by `documentService.archive`.
- `DOCUMENT_REPLACED` — written by `documentService.confirm` when prior docs were superseded.

## API/Interface Changes

### No new endpoints. Existing surface covers everything:

- `GET /documents/:id/download` — used by View + Download.
- `PATCH /documents/:id/archive` — used by Delete. **Add `requireRole(['ADMIN'])` guard.**
- `POST /documents/presign` + `POST /documents/:id/confirm` — used by Replace.

### New components

- `DocumentDetailDrawer` — registered as `documentDetail` in `drawerRegistry.ts`. Drawer prop: `documentId: string`. Opened via `useDrawerActions().openDrawer('documentDetail', { documentId })`.
- `ExpiryBadge` — pure UI. Prop: `expiresAt: Date | string | null | undefined`. Returns `null` when null or > 30 days.

### Modified components

- `DocumentTable` — Actions column with kebab (View · Download · Replace · Delete), `ExpiryBadge` in expiry cell, custom-label rendering for OTHER, row click opens detail drawer.
- `DocumentUploadDrawer` — required `customLabel` text field when `OTHER` is selected.
- `DOC_TYPE_CONFIG` + `DOCUMENT_CONTEXTS` (`features/documents/constants.ts`) — entries and per-context allowlists for all 25 new types and the `OTHER` allowlist additions on Load contexts.

### New sagas + slice handlers

- `archiveDocumentSaga` — `PATCH /documents/:id/archive`, removes from entity slice on success.
- `getDownloadUrlSaga` — `GET /documents/:id/download`, returns URL.

## Technical Context

### Existing Code to Reuse

- `documentService.archive()` (dispatch-api `src/documents/services/documentService.ts`) — backs Delete.
- `documentService.getDownloadUrl()` (same file) — backs View + Download.
- `documentRepoPrisma.archiveByEntityAndType()` (dispatch-api `src/documents/repositories/documentRepositoryPrisma.ts`) — auto-archives prior docs of same type during `confirm`. Replace inherits this for free.
- `DocumentUploadDrawer` (dispatch-ui `src/features/documents/components/DocumentUploadDrawer/index.tsx`) — Replace reuses with `preselectedDocType` + `lockDocType=true`.
- `DocumentPicker` (dispatch-ui `src/components/DocumentPicker/index.tsx`) — already generic; picks up new types automatically from `DOC_TYPE_CONFIG`.
- `DOC_TYPE_CONFIG` + `DOCUMENT_CONTEXTS` (dispatch-ui `src/features/documents/constants.ts`) — single source of truth.
- `drawerRegistry` + `useDrawerActions().openDrawer` (dispatch-ui `src/features/ui/drawerRegistry.ts`) — drawer lifecycle.
- `requireRole(['ADMIN'])` (dispatch-api `src/middleware/auth.ts`) — guards archive route.
- `useAuth()` (dispatch-ui `src/hooks/useAuth.ts`) — UI role gate.
- `auditLogRepo.create()` (port in dispatch-api `src/auth/types/auditLogPort.ts`) — audit entries.
- MUI `Drawer`, `Menu`, `Chip`, `IconButton` — kebab, badge, drawer surface.

### Key Decisions

- **Drawer over dialog for preview** — consistent with `DocumentUploadDrawer` and existing drawer registry. Slides from right; full-width on mobile (≤768px), ~720px on desktop.
- **Replace = upload-with-supersede** — no new endpoint. The existing `confirm` flow already archives prior docs of the same `type` for `onePer` types. Audit log captures the swap.
- **Soft delete via existing archive endpoint** — `isArchived` already filters list responses. No new schema; recovery-friendly.
- **Keep prior S3 object on Replace** — cheapest, recovery-friendly, matches soft-delete philosophy. Audit log records old S3 key for forensics.
- **Expiry badge is generic on `expiresAt`** — schema field is generic; one component covers every type. Track 6's insurance badge becomes one specific consumer.
- **Tab refactor skipped** — `DocumentTable` is the actual reuse layer. Existing custom tabs (Carrier, Load) host entity-specific UX (e.g., Load's rate-con prompt) that doesn't belong in a generic component.
- **Browser-native PDF viewer** — `<iframe>` instead of pulling in PDF.js. Saves a heavy dep for MVP.
- **`OTHER` requires a custom label everywhere** — and is now enabled on Load contexts so dispatchers always have an escape hatch.
- **Email-out, drag-out, version-history UI, dashboards/notifications, global library, hard delete** — all deferred.

## Out of Scope

- Email-from-app and drag-out to email/desktop (Chrome-only DownloadURL trick — deferred).
- Version history UI (replace logs supersession, but no browse/restore yet).
- Bulk multi-zip download beyond the existing `bulkDownload` endpoint.
- Rename / reassign / move document between entities.
- Global Document Library page with cross-entity search.
- Expiry dashboard, in-app notifications, email digests, "Request reupload" SMS.
- Shareable signed external links with explicit expiry/revocation.
- Hard delete (soft-delete is intentional for recoverability).
- Tab consolidation / refactor — `DocumentTable` already provides the reuse layer; tab wrappers stay as-is so entity-specific UX (Load's rate-con prompt) is preserved.
