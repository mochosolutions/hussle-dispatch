## Problem

The carrier portal and dispatcher app have divergent document-upload pipelines — different UI components, different Redux sagas, different API clients, different backend services. The portal's path never writes `Document.expiresAt` and never publishes the `document.confirmed` event. This causes silent drift between `Carrier.insuranceCertOnFile/insuranceExpiry` and the actual `Document` rows, and it blocks the planned migration of those flags to derived-on-read.

Concrete evidence from dev DB (2026-05-25):
- All `Document.expiresAt` are NULL even when `Carrier.insuranceExpiry` is populated.
- QA Test Carrier has 3 non-archived INSURANCE_CERT docs (one `uploaded`, two `pending`), with no clear authoritative row.
- 2 of 3 SIGNED Agreements have stale `Carrier.signedAgreementId` projections.
- Portal `confirmDocument` doesn't publish `document.confirmed`, so 4 other subscribers (`loadTimestamp`, `notification`, `documentArchive`, `invoiceReadiness`) never fire for portal-confirmed carrier docs.

The same single-document upload state machine is also copy-pasted three times inside the dispatcher app itself (`BolUploadAlert`, `StatusChangeDialog` x2).

## Solution Overview

Three layers of convergence. **Backend (Phases 1–2) ships independently** and unblocks the derived-values migration even if frontend work pauses.

### Phase 1 (backend) — Service convergence + endpoint shape

- Rewrite `portalDocumentsService` as an **adapter that delegates** (per D5) to `createDocumentService`. Translates input (carrier-portal mapper shape) → dispatcher service input shape; calls dispatcher service; translates output → existing v2-API-client expected shape (`{ documentId, uploadUrl, fields }`). Pass `uploadedByUserId: null` for portal context (per MI4 — carrier has no User row). Portal's HTTP controller stays as a thin auth-checking wrapper.
- Add `expiresAt` to portal `presignDocumentValidator` + `presignDocumentMapper`.
- Rename `insuranceExpiry` → `expiresAt` on `confirmDocumentValidator` + `confirmDocumentMapper`. Clean break (dev mode, no backward-compat shim).
- Result: `Document.expiresAt` always written, `document.confirmed` always published from portal flow.

### Phase 2 (backend) — Verify + new tests

- Add `portalDocumentsService.test.ts` modeled on `portalEquipmentService.test.ts`.
- Verify: portal upload writes `Document.expiresAt`, publishes event, triggers `carrierComplianceSubscriber`.
- Run `(cd hussle-app-dispatch-api && npm run validate)`.

### Phase 3 (frontend) — Shared components + shared saga helper

- Extract `ComplianceForm` from `DocumentUploadDrawer/index.tsx:103-161` into `src/components/ComplianceForm/index.tsx`. Add validation per D4: when `DOC_TYPE_CONFIG[documentType].requiresExpiry === true`, disable the Submit/Upload button until expiry is filled.
- Add `requiresExpiry: true` to `DOC_TYPE_CONFIG[DocumentType.INSURANCE_CERT]` in `features/documents/constants.ts`. Default `false` for all other types.
- Create `src/components/SingleDocumentUpload/index.tsx` as a **dumb component** (D2). API: `{ documentType, accept?, maxFileSize?, status, errorMessage?, fileName?, onUpload, onReset }`. Owns the UI state machine, NOT the dispatch. Gates ComplianceForm rendering on `DOC_TYPE_CONFIG[documentType].compliance === true` (per CR2 — `compliance` flag, not `metadataFields`). Defaults: `accept = '.pdf,.jpg,.jpeg,.png,.webp'`, `maxFileSize = 10 * 1024 * 1024`.
- Extract `uploadFileViaPresign` saga helper to `features/documents/store/sagas/uploadFileViaPresign.ts`. Per D3, accepts adapter functions that return normalized shapes:
  ```typescript
  interface NormalizedPresign { documentId: string; presignedUrl: string; }

  function* uploadFileViaPresign(input: {
    file: File;
    documentType: DocumentType;
    entityType: DocumentEntityType;
    entityId: string;
    expiresAt?: string;
    metadata?: Record<string, string>;
  }, deps: {
    presignFn: (presignInput: {
      fileName: string; fileSize: number; mimeType: string;
      type: DocumentType; entityType: DocumentEntityType; entityId: string;
      expiresAt?: string; metadata?: Record<string, string>;
    }) => Promise<NormalizedPresign>;
    confirmFn: (documentId: string, confirmInput?: {
      expiresAt?: string; metadata?: Record<string, string>;
    }) => Promise<unknown>;
  }): Generator<unknown, unknown, unknown>
  ```
  Helper does NOT have try/catch (per D6); errors propagate to caller.
- Refactor dispatcher `uploadDocumentSaga` to call `uploadFileViaPresign` with adapter functions that wrap `presignDocument` / `confirmDocument` from `utils/api/documents/documentApi.ts`. Dispatcher's `presignDocument` returns `{ presign: { documentId, presignedUrl, ... } }` — adapter unwraps to `{ documentId, presignedUrl }`. Keep all existing slice updates + notify dispatches inside saga's try/catch.
- Refactor portal `uploadDocumentSaga` to call `uploadFileViaPresign` with adapter functions that wrap `presignDocumentV2` / `confirmDocumentV2` from `utils/api/carrierPortal/v2.ts`. Token sourced via `yield select(selectToken)` (per MI1 — actual selector name is `selectToken`, not `selectInviteToken`). Adapter passes token + maps to normalized shape. Keep all existing portal slice updates inside saga's try/catch.

### Phase 4 (frontend) — Call-site refactors

- `BolUploadAlert` uses `<SingleDocumentUpload>`. Owns its own `clientId`, `dispatch(uploadDocumentRequest(...))`, and selector reads. Wraps in Alert for layout.
- `StatusChangeDialog` uses `<SingleDocumentUpload>` twice (rate con + BOL). Owns its own clientIds, dispatches, and selectors.
- Portal `AgreementListView` uses `<SingleDocumentUpload>` per slot. Owns its own per-slot tracking, dispatches `carrierPortalV2Actions.uploadDocument(...)` (which now triggers the helper-using portal saga). Reads upload state from existing portal selectors.
- Update v2 API client in `utils/api/carrierPortal/v2.ts` for the `insuranceExpiry` → `expiresAt` rename + add `expiresAt` to presign function payload.

Auth boundary (Bearer invite token vs cookie) stays. Each saga retains its own auth context, its own API client, its own success/failure dispatches, its own state slice. Only the presign → S3 → confirm orchestration is shared via the helper.

## User Flows

### Flow 1 — Carrier portal: upload insurance certificate

1. Carrier reaches the Documents step in onboarding; the agreement list shows a row for "Insurance Certificate" with an Upload button.
2. Carrier clicks Upload → hidden file input opens.
3. Carrier picks a PDF/image.
4. Because `INSURANCE_CERT` is a compliance type, the `<ComplianceForm>` panel appears inline with an Expiration Date field.
5. Carrier enters the expiry and clicks "Upload".
6. Parent (`AgreementListView`) dispatches `carrierPortalV2Actions.uploadDocument({ file, documentType, expiresAt, metadata, ... })`.
7. Portal saga calls `uploadFileViaPresign(input, { presignFn: portalPresign(token), confirmFn: portalConfirm(token) })`.
8. Helper: presign → S3 PUT → confirm. Backend portal service delegates to `createDocumentService` — `Document.expiresAt` written, `document.confirmed` published, `carrierComplianceSubscriber` updates `Carrier.insuranceCertOnFile` + `Carrier.insuranceExpiry`.
9. Portal saga dispatches `carrierPortalV2Actions.uploadDocumentSuccess({ documentType })` (existing behavior).
10. UI shows checkmark via existing `isUploaded` selector. After refresh, `session.documents` repopulates and the row stays checked.

### Flow 2 — Dispatcher: upload BOL from load detail

1. Dispatcher opens a load detail page; `Alert` shows "Awaiting signed BOL" with Upload button.
2. Dispatcher picks a file.
3. `BOL_SIGNED` is not a compliance type → no `ComplianceForm`. Parent (`BolUploadAlert`) dispatches `uploadDocumentRequest({ file, documentType: BOL_SIGNED, ... })` immediately on file pick.
4. Dispatcher saga calls `uploadFileViaPresign(input, { presignFn: presignDocument, confirmFn: confirmDocument })`.
5. Helper: presign → S3 PUT → confirm. `document.confirmed` published, `loadTimestampSubscriber` updates `Load.bolReceivedAt`.
6. Dispatcher saga dispatches `documentActions.addOne(...)` + `uploadDocumentSuccess({ clientId })` + `notify(...)`. Load detail refetches; alert hides.

### Flow 3 — Dispatcher: status change with required uploads

1. Dispatcher transitions a load to a status requiring rate-con or BOL.
2. `StatusChangeDialog` opens with two `<SingleDocumentUpload>` panels.
3. Dispatcher uploads each; modal Confirm enabled when both complete.

### Key Decisions

See **Decisions Locked In** at the top for the binding answers.

- **Auth boundaries stay separate.** Portal endpoints + dispatcher endpoints are independent. Each saga uses its own API client. No backend auth middleware change.
- **Two sagas, one helper (D1).** The duplication being eliminated is the presign → S3 → confirm orchestration. Everything context-specific (auth, slice updates, notifications, optimistic state) stays in each feature's saga.
- **Dumb `<SingleDocumentUpload>` (D2).** Component owns UI state machine; parent owns dispatch and selector reads. Maximally reusable across upload contexts.
- **Phase ordering: backend first, then frontend.** Phases 1–2 ship independently and unblock the derived-values migration even if frontend work pauses.
- **`ComplianceForm` ALWAYS shows the expiration date input** for compliance doc types — unchanged behavior.
- **Refactor preserves visible UX exactly** across all 4 call sites. For `AgreementListView`, expiry capture moves to *before* upload (was: after S3) — aligns with dispatcher UX and prevents abandoned uploads.
- **Backfill of `Document.expiresAt` from `Carrier.insuranceExpiry`** is NOT in scope — tracked in derived-values migration.
