## Notes

- **No DELETE rows.** Portal `uploadDocumentSaga.ts` STAYS (was DELETE in prior revision). Portal `carrierPortalSlice.ts` STAYS unchanged for upload-related state. `localUploadedTypes` STAYS.
- **No new selectors.** Portal continues using existing `selectDocuments` + `localUploadedTypes` pattern.
- **No `loadSessionSaga` modification.** No `documentActions.addMany` seeding.
- **No `authContext` discriminator** on `uploadDocumentRequest` payload.
- **Phase 1–2 (backend) is independently shippable** and unblocks the derived-values migration. Phase 3–4 (frontend) can land on a separate PR/branch.
- **D2 (dumb component) consequence:** `<SingleDocumentUpload>` analog is `partial` rather than `exact`. The visual states (idle / awaiting-compliance / uploading / success / error) and ComplianceForm composition are copied from BolUploadAlert + DocumentUploadDrawer. The dispatch, clientId generation, and selector subscription are removed — those become parent responsibilities.
- **D3 (adapter pattern)** — Each saga wraps its raw API client function in a small adapter that returns a normalized `{ documentId, presignedUrl }`. Adapters live inline in the saga (no need for separate files). Without this, the dispatcher saga can't share a helper with the portal saga because their API client return shapes diverge (`{ presign: { ... } }` vs `PresignResponseV2`).
- **D4 (requiresExpiry)** — `INSURANCE_CERT` gets `requiresExpiry: true` in `DOC_TYPE_CONFIG`. Form validation prevents empty-expiry uploads for INSURANCE_CERT. Other compliance types stay optional (W9, CARRIER_PACKET — no real expiry).
- **D5 (portal service as adapter)** — `portalDocumentsService` translates: v2 mapper input → dispatcher service input; calls dispatcher service; translates output back to v2 client's expected shape (`{ documentId, uploadUrl, fields }`). Future cleanup: align v2 contract to dispatcher's `{ documentId, presignedUrl, expiresIn }` and remove the output translation. Not in this PRD.
- **D6 (error handling)** — Helper throws on any step failure. Each saga's try/catch handles failure dispatch. Helper has no try/catch of its own.
- **MI1 (token selector)** — Actual selector name is `selectToken` (not `selectInviteToken` as initially written). Located at `features/carrier-portal/store/selectors/carrierPortalSelectors.ts:28`.
- **MI4 (uploadedByUserId)** — Portal context passes `null` since the carrier has no User row. `documentService.presign` accepts null already (input field is optional via prisma).
- **C1 clean break** — grep for `insuranceExpiry` in `hussle-app-dispatch-ui/src/features/carrier-portal/` and `utils/api/carrierPortal/` to catch all call sites that need updating.
- **C2 single-file scope** — `<SingleDocumentUpload>` accepts ONE file. Multi-file is a future PRD.
- **D7 (file validation)** — Component validates `accept` + `maxFileSize` BEFORE invoking `onUpload`. Invalid files render an internal error state (local component state, not the `status` prop) with a generated message. Parent never sees invalid files.
- **D8 (V2 confirm body)** — `confirmDocumentV2` body shape changes from `{ key: string }` to `{ expiresAt?, metadata? }`. The legacy `key` field is dropped. Backend `createDocumentService.confirm` looks up `documentType` from the Document row by id (matches dispatcher pattern), so the body doesn't need `type` either.
- **D9 (AgreementListView fileName tracking)** — Parent adds per-slot `uploadingFileName` to local state (mirrors existing `uploadingType`). Captures filename at `onUpload` time; passes to `<SingleDocumentUpload>` as `fileName` prop; after session refresh, sourced from `session.documents[i].fileName`.
- **DocumentUploadDrawer.test.tsx is safe** — verified the test imports `DocumentUploadDrawer` + `OtherLabelForm` from `./index`, not the inline `ComplianceForm`. Extracting the form to a shared module does not require test changes.
- **BolUploadAlert has no existing test** — verified by file search. Adding `BolUploadAlert.test.tsx` as NEW (see Phase 4 table).
