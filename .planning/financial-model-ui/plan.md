## Problem

The dispatch UI still uses the old financial field names (`carrierRate`, `dispatchFee`, `partnerSplit`) and computes driver economics client-side with hardcoded constants. The backend now provides accurate, server-computed financials (carrier payout, company margin, driver pay, dispatcher commission, company net) but the UI doesn't consume them. Additionally, there are no screens for settlements, IFTA reporting, or expense management — dispatchers have to use external tools for these workflows.

## Solution Overview

Two parts in one plan:

**Part A** — Update existing load components to use new financial field names and API-computed values. Remove client-side financial calculations and hardcoded constants.

**Part B** — Build new accounting section (`/accounting`) with dedicated screens for settlements, IFTA reports, and expense management. P1 screens for earnings dashboard and fleet P&L.

Migration B (DB column renames + table drops) is excluded — it will be a separate plan after all financial model work is complete.

## User Flows

### View Settlement Detail
1. User navigates to Accounting → Settlements
2. Sees paginated list of settlements with status badges (DRAFT, APPROVED, PAID, DISPUTED)
3. Clicks a settlement row
4. Sees settlement header: settlement number, status, period, carrier name, driver name
5. Sees totals card: gross revenue, dispatch fee, expenses, net earnings, total miles
6. Sees line items table grouped by type (loads, deductions, expenses, adjustments)
7. For DRAFT status: sees Approve button
8. For APPROVED status: sees Mark Paid button (with payment method/reference form)
9. For any non-PAID status: sees Dispute button (with reason input)

### Generate Settlement
1. User clicks "Generate Settlement" button on settlements list
2. Dialog: select carrier, optional driver, optional vehicle, period start/end
3. Submit calls `POST /api/v1/settlements/generate`
4. On success: navigates to the new settlement detail page
5. On error (no loads, overlap, external carrier): shows error message

### View IFTA Report
1. User navigates to Accounting → IFTA
2. Default view: current quarter, all vehicles (fleet-wide)
3. User can change quarter/year via selector
4. User can filter to single vehicle via dropdown
5. Table shows: state code, miles driven, fuel gallons, fuel cost per state
6. Bottom row: fleet-wide or per-vehicle totals (total miles, total gallons, total fuel cost, avg MPG)
7. Empty state: "No IFTA data for Q{X} {YEAR}"

### Log Expense (Quick Add)
1. User clicks "Add Expense" on expenses page (or global FAB)
2. Modal opens with: category dropdown, amount, date, vehicle selector
3. If category is FUEL: expands to show gallons, state, price-per-gallon fields
4. Submit creates expense via API
5. Modal closes, list refreshes

### Key Decisions
- **API-computed financials** — All financial values come from the API. The UI displays them but does not compute them.
- **String-typed Decimals** — Financial values arrive as strings from the API. Display using `Number()` conversion or formatted currency string.
- **No Migration B** — DB column renames are a separate plan. The API returns BOTH old and new field names during the transition.
- **Accounting as top-level section** — New `/accounting` route group with sidebar sub-nav.
- **Redux for settlements only** — Settlements have CRUD operations and complex state; use Redux + Saga. IFTA and expenses are read-heavy with simple state; use local component state + useEffect.
- **P1 screens deferred** — Earnings dashboard and fleet P&L are P1; implement if time permits.
