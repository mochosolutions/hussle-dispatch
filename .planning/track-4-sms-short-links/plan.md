# Driver SMS Short-Link Service + Copy Refresh (Track 4)

> Generated by /prd-refine on 2026-04-26

## Problem

Track 3 driver SMS prompts shipped and live testing surfaced three problems with the message format:

1. **No brand identity.** Body reads `Load #N: please check in. {url}`. Drivers receiving an SMS from an unknown number have no signal that the message is from their dispatcher's tooling — high risk of being ignored or marked as spam.
2. **Long, ugly URL.** The check-in link is `http://localhost:5173/driver-portal/{uuid}` (≈55 chars in dev, more in prod). Eats SMS budget, looks like phishing, and reduces tap rate.
3. **Same body for every anchor.** DISPATCHED, PRE_PICKUP, POST_PICKUP, TRANSIT_INTERVAL, and MANUAL all share the generic `please check in` copy. The driver gets no context about *why* they're being pinged or what the load is.

Drivers bear the cost — every ignored SMS becomes a manual phone call from the dispatcher. Fixing message format is the cheapest leverage on engagement.

## Solution Overview

Three coordinated changes:

1. **In-house short-link service** in dispatch-api — SMS URLs become `https://api.hussle.dev/s/{8-char-slug}` (~32 chars). Self-hosted (no Twilio Link Shortener, Bitly, or vanity domain) — zero recurring cost, lives on the existing dispatch-api domain.
2. **Brand-prefixed body copy** — every SMS leads with `Hussle:` so drivers immediately recognize the source.
3. **Anchor-specific templates** — DISPATCHED gets a rich load-summary message (origin/destination, pickup/delivery times, equipment); PRE_PICKUP / POST_PICKUP / TRANSIT_INTERVAL / MANUAL get short single-segment messages tailored to their intent. Templates are hard-coded in code for MVP; org-configurable templates are P1.

Existing `trackingTokenService` keeps owning portal-token issuance; the short-link service stores the long URL and exposes a public `GET /s/:slug` redirect.

## Capabilities

### Must Have (P0)

- New `ShortLink` model storing `slug`, `targetUrl`, `loadId`, `purpose`, `expiresAt`, `clickCount`, `lastClickedAt`
- Random 8-char base62 slug generator with retry-on-collision (P2002)
- `GET /s/:slug` public (unauthenticated) redirect endpoint — 302 to `targetUrl`, 404 if missing or expired, increments click counter fire-and-forget
- SMS prompt worker mints a fresh short link per send
- **Anchor-specific message templates** — five hard-coded templates, one per `SmsPromptAnchor`. DISPATCHED is rich (load summary); others are terse single-segment messages
- **Template composition function** — `composeSmsBody({ anchor, load, shortUrl })` returns the right body. Designed so future fields (rate, custom org templates) plug in without rewriting call sites
- Confirm modal preview (`SendSmsPromptModal`) shows the **MANUAL** template (since manual sends are what the modal triggers)
- Short link `expiresAt` matches the underlying tracking token's expiry (7 days)
- Extend `LoadSchedulerQueryPort.findForScheduling` to also project: `equipmentType`, first PICKUP stop's `city`/`state`/`appointmentStart`, last DELIVERY stop's `city`/`state`/`appointmentStart` (needed for the DISPATCHED rich body)

### Nice to Have (P1 — defer)

- **Rate display in DISPATCHED template** — the composer should accept an optional `rate` field; just don't populate it for MVP. Adding it later is a one-line change in `composeSmsBody` plus the projection.
- **Org-configurable templates** — store templates per-org in `OrgSettings` with placeholders like `{loadNumber}`, `{originCity}`, `{url}`. UI form to edit. Hard-coded fallback when not set.
- **Reefer setpoint temperature** — no schema field today; if/when added on `Load` (`setTemperatureF`), the DISPATCHED template can include `❄️ Reefer (34°)` instead of just `❄️ Reefer`.
- Click analytics dashboard surfacing `clickCount` / `lastClickedAt` per load
- Cleanup job for expired short links (DB grows ~1 row per SMS send — low pressure)
- Custom HTML 404 page for missing slugs (JSON 404 is acceptable for MVP)
- Vanity short domain swap (`PUBLIC_SHORT_BASE_URL` is env-driven so future swap is non-breaking)

## Message Templates

All templates lead with `Hussle:` and place the short URL on its own final line. `{loadNumber}` is required; other fields apply only to DISPATCHED.

### DISPATCHED — rich load summary

Multi-segment (UCS-2 due to emoji). Fires once per load on initial dispatch. Cost worth it for first-impression engagement.

```
Hussle: Load #{loadNumber} dispatched
{originCity}, {originState} → {destCity}, {destState}
🕖 PU: {pickupTime} | 🕛 DEL: {deliveryTime}
{equipmentLine}
{shortUrl}
```

- `pickupTime` / `deliveryTime`: `appointmentStart` formatted `h:mm AM/PM` in the stop's local TZ (resolve via `city`/`state`; fall back to UTC labeled `UTC` if unknown)
- `equipmentLine`: emoji + label, no temperature for MVP
  - `REEFER` → `❄️ Reefer`
  - `DRY_VAN` → `🚛 Dry Van`
  - `FLATBED` → `🛻 Flatbed`
  - other / null → omit the line entirely
- If origin or destination stop is missing or lacks city/state, omit the route line and fall back to a degraded body containing only `Hussle: Load #{loadNumber} dispatched\n{shortUrl}`

### PRE_PICKUP — pickup soon

```
Hussle: Load #{loadNumber} pickup is coming up. Confirm you're en route.
{shortUrl}
```

GSM-7 single segment.

### POST_PICKUP — escalation

```
Hussle: Load #{loadNumber} — pickup window passed. Update status now.
{shortUrl}
```

GSM-7 single segment. Tone is firmer ("now", "passed").

### TRANSIT_INTERVAL — recurring location ping

```
Hussle: Load #{loadNumber} status check. Tap to share current location.
{shortUrl}
```

GSM-7 single segment. Cheapest per send (recurring).

### MANUAL — dispatcher initiated

```
Hussle: Load #{loadNumber} needs a check-in.
{shortUrl}
```

GSM-7 single segment. Generic on purpose — dispatcher's reason for sending varies.

## User Flows

### Flow 1 — SMS prompt worker sends a check-in

1. Worker dequeues `sms.prompt.due` for a load (carries the `anchor`)
2. Worker calls `trackingTokenService.getOrCreateDriverToken(loadId)` → returns `{ token, expiresAt }` (existing behavior)
3. Worker calls extended `loadSchedulerQuery.findForScheduling(loadId)` → returns load + stops + equipment (new fields for DISPATCHED template)
4. Worker builds the long URL: `${TRACKING_BASE_URL}/driver-portal/${token}`
5. Worker calls `shortLinkService.createShortLink({ targetUrl, loadId, purpose: 'DRIVER_PORTAL', expiresAt })` → returns `{ slug }`
6. Worker builds short URL: `${PUBLIC_SHORT_BASE_URL}/s/${slug}`
7. Worker calls `composeSmsBody({ anchor, load, shortUrl })` → returns anchor-appropriate body (rich for DISPATCHED, terse for others)
8. Worker calls `smsService.sendSms({ to, body })` (existing path)
9. Worker writes `messageSid` + `sentAt` to `SmsPromptSchedule` (existing path)

### Flow 2 — Driver taps short link

1. Driver opens SMS, taps `https://api.hussle.dev/s/x9k2qa`
2. Browser hits `GET /s/x9k2qa` on dispatch-api (no auth)
3. Controller calls `shortLinkService.resolveSlug('x9k2qa')`
4. Found and not expired → increment `clickCount`, set `lastClickedAt` (fire-and-forget), return 302 to `targetUrl`
5. Missing or expired → return 404 JSON `{ errors: [{ message: 'Link not found or expired' }] }`
6. Driver lands on `${TRACKING_BASE_URL}/driver-portal/${token}` — existing portal flow handles token validation and load scoping

### Flow 3 — Dispatcher previews SMS in confirm modal

1. Dispatcher clicks "Send Check-in SMS" on load detail
2. Modal renders preview Box with the **MANUAL** template (since the modal triggers manual sends):
   - Line 1: `Hussle: Load #${loadNumber} needs a check-in.`
   - Line 2: italic muted `<short check-in link>` (placeholder — real slug minted only on send)
3. Dispatcher clicks Send → existing flow continues. (Auto-anchor templates aren't previewed in the UI — they fire from the worker.)

## Data Requirements

### New table: `ShortLink`

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | PK |
| `slug` | string | Unique. 8 chars base62. |
| `targetUrl` | text | Full URL the slug redirects to |
| `loadId` | uuid? | Nullable. No FK enforced (purpose may broaden) |
| `purpose` | string | `'DRIVER_PORTAL'` for now; future-proof for other channels |
| `expiresAt` | timestamptz | When the slug stops resolving |
| `clickCount` | int | Default 0 |
| `lastClickedAt` | timestamptz? | Set on each successful resolution |
| `createdAt` / `updatedAt` | timestamptz | Standard |

Indexes: `@unique([slug])`, `@@index([loadId])`, `@@index([expiresAt])`.

No FK on `loadId` — keeps writes cheap and avoids cascade complexity for an analytics-flavored row.

## API/Interface Changes

### New endpoint

- `GET /s/:slug` — public, unauthenticated. 302 redirect to `targetUrl` on hit. 404 with JSON envelope on miss/expired. Mounted at `app.use('/s', shortLinksRouter)` (NOT under `/api/v1/`).

### Modified internal API

- `smsPromptWorker` gains two injected deps: `shortLinkService` and `publicShortBaseUrl: string`
- `SmsService.sendSms` is unchanged (this feature only changes the body the worker passes in)

### New env var

- `PUBLIC_SHORT_BASE_URL` (default `http://localhost:3001` in dev, api hostname in prod) — added to `src/config/env.ts` and documented in `.env.example`

### UI surface modified

- `SendSmsPromptModal` (dispatch-ui) — preview text only, no API client or saga changes

## Technical Context

### Existing Code to Reuse

- **`trackingTokenService.getOrCreateDriverToken`** (`hussle-app-dispatch-api/src/notifications/services/trackingTokenService.ts:47`) — keeps owning portal token issuance. Returns `{ token, expiresAt }` which the short-link service uses for `targetUrl` and `expiresAt`.
- **`sms-prompts/` module structure** (`hussle-app-dispatch-api/src/sms-prompts/compositionRoot.ts` + `index.ts`) — pattern for the new `short-links/` module: per-module DI, factory-built router, side-effect `import './short-links';` in `app.ts`.
- **Repo pattern** (`hussle-app-dispatch-api/src/sms-prompts/repositories/smsPromptScheduleRepositoryPrisma.ts`) — port + Prisma impl shape.
- **Migration timestamp convention** (`prisma/migrations/20260422000000_add_sms_prompt_schedule/`) — `YYYYMMDDHHmmss_description`.
- **`smsPromptWorker.ts:108-112`** — exact insertion point for the new body construction.
- **`SendSmsPromptModal/index.tsx:50-57`** — `previewBody` block to update.

### Key Decisions

- **Build vs. buy short-link service** → build. Tight budget rules out Twilio Link Shortener (~$0.0025/click) and Bitly (vendor dep). Self-hosted is zero recurring + reuses existing infra.
- **Slug host on dispatch-api domain, not vanity short domain** → reuse api domain. Saves ~$10/yr; drivers don't read URLs. `PUBLIC_SHORT_BASE_URL` is env-driven so swapping later is non-breaking.
- **Mount at `/s` not `/api/v1/s`** → keeps total URL length minimal. Three extra path chars × every SMS send adds up.
- **Fresh slug per send (no reuse)** → simpler. Avoids cache-invalidation when the underlying token rotates. Storage cost negligible (~1 row per SMS).
- **No FK from `loadId` to `Load`** → keep writes cheap and avoid cascade complexity for an analytics-flavored row.
- **Random opaque slug, not human-readable** → don't reuse `slugValidator.ts:80` `generateSlug`. That utility produces deterministic kebab-case slugs from input strings; short links want unguessable random IDs.
- **8 chars / base62** → 218 trillion combinations, collision-resistant. Retry on `P2002` is defensive only.
- **Click tracking columns now, dashboard later** → adding `clickCount`/`lastClickedAt` is one column each. Defer the UI until ops asks.

### Research Findings

None — all decisions came from existing repo patterns and the conversation, no web search needed.

## Acceptance Criteria

1. New `ShortLink` Prisma model exists with the fields and indexes above; migration applies cleanly via `npx prisma migrate dev`.
2. `generateShortSlug()` returns an 8-char string drawn from `[a-zA-Z0-9]`; over 1000 calls, no two outputs are equal (statistical, not exhaustive — verify in unit test).
3. `shortLinkService.createShortLink({ targetUrl, loadId, purpose, expiresAt })` writes a row and returns `{ slug }`. On `P2002` collision the service retries up to 3 times before throwing.
4. `shortLinkService.resolveSlug(slug)` returns `{ targetUrl }` for an active row, increments `clickCount`, and sets `lastClickedAt`. Returns `null` when slug missing OR `expiresAt < now()`.
5. `GET /s/:slug` returns HTTP 302 with `Location: <targetUrl>` for an active slug. Returns 404 with JSON `{ errors: [{ message: 'Link not found or expired' }] }` for missing/expired. Endpoint is publicly accessible (no `appAuth`).
6. The route resolves at `/s/:slug` (NOT under `/api/v1/`).
7. `composeSmsBody({ anchor, load, shortUrl })` returns the correct template per anchor:
   - DISPATCHED: matches `/^Hussle: Load #\d+ dispatched\n.+ → .+\n🕖 PU: .+ \| 🕛 DEL: .+\n(❄️ Reefer|🚛 Dry Van|🛻 Flatbed)?\n?https?:\/\/.+\/s\/[a-zA-Z0-9]{8}$/`
   - PRE_PICKUP: `/^Hussle: Load #\d+ pickup is coming up\. Confirm you're en route\.\nhttps?:\/\/.+\/s\/[a-zA-Z0-9]{8}$/`
   - POST_PICKUP: `/^Hussle: Load #\d+ — pickup window passed\. Update status now\.\n.+$/`
   - TRANSIT_INTERVAL: `/^Hussle: Load #\d+ status check\. Tap to share current location\.\n.+$/`
   - MANUAL: `/^Hussle: Load #\d+ needs a check-in\.\n.+$/`
8. DISPATCHED template gracefully degrades when origin or destination stop missing city/state — body falls back to `Hussle: Load #N dispatched\n{shortUrl}` rather than throwing.
9. DISPATCHED template renders pickup/delivery times in the stop's local TZ derived from city/state; falls back to UTC labeled `UTC` when TZ resolution fails.
10. Existing test in `smsPromptWorker.test.ts` is updated to cover all five anchor branches; `shortLinkService.createShortLink` mock is verified called with the right `targetUrl`, `loadId`, `purpose='DRIVER_PORTAL'`, and `expiresAt`. New unit tests for `composeSmsBody` cover each anchor + the DISPATCHED-degraded path + the unknown-equipment-omits-line path.
11. `LoadSchedulerQueryPort.findForScheduling` projection extended to include `equipmentType`, first PICKUP stop's `city`/`state`/`appointmentStart`, last DELIVERY stop's `city`/`state`/`appointmentStart`. Existing scheduler subscriber tests still pass.
12. `SendSmsPromptModal` preview Box renders two lines: `Hussle: Load #{loadNumber} needs a check-in.` then italic `<short check-in link>` (MANUAL template). Existing modal test updated.
13. `PUBLIC_SHORT_BASE_URL` is read from env in `src/config/env.ts` and injected into `smsPromptWorker` via the `sms-prompts` composition root.
14. End-to-end smoke: dispatching a load with a Twilio-receiving driver phone results in a Twilio Console body matching the DISPATCHED rich format with origin → destination, pickup/delivery times, equipment, and short URL. Tapping the short URL on a phone produces a 302 to the driver portal scoped to the load.
