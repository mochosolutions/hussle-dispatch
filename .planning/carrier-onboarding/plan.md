# Carrier Onboarding

> Generated by /prd-refine on 2026-03-30

## Problem

Dispatchers manually enter carrier data — a slow, error-prone process that delays carrier activation. Carriers don't have a way to provide their own information, sign agreements, or upload documents. The minimum rate per mile (critical for Load Intelligence scoring) requires a cost profile that currently only exists after vehicle expenses are manually entered post-activation.

## Solution Overview

A carrier portal accessible via invite link where carriers complete a phased conversational interview (TurboTax-style, one question at a time). On completion, the dispatcher reviews and approves the application. Approval activates the carrier with a live minimum rate per mile in Load Intelligence. Subsequent phases add self-registration with FMCSA verification and post-activation workflows (cost profile refinement, reminders, document expiry monitoring).

### Phase Summary

| Phase | Focus | Key Deliverables |
|-------|-------|-----------------|
| **1** | Invite-only portal + conversational interview + doc signing + approval | Portal auth, conversational form system, 6-phase interview, doc signing, approval gate, min rate -> Load Intel |
| **2** | Self-registration + FMCSA | Public registration, email verification, FMCSA lookup on MC/DOT entry, tier classification |
| **3** | Post-activation workflows | Cost profile Version 2 via expense tab, configurable reminders, document expiry monitoring |

### Dependency Graph

```
Phase 1 (Stories 1-18)
  ├── Phase 2 (Stories 19-24) — extends portal with self-reg + FMCSA
  └── Phase 3 (Stories 25-30) — post-activation (can parallel Phase 2)
```

Phase 1 is the foundation. Phases 2 and 3 can be built in parallel after Phase 1 ships.

## User Flows

### Two Entry Paths Converging

- **Invited (Phase 1):** Dispatcher creates partial carrier (name, email, phone, MC#) -> sends branded invite -> carrier opens link -> sees pre-filled details -> confirms email -> begins with head start
- **Self-serve (Phase 2):** Carrier finds landing page -> enters email -> verifies with 6-digit code -> begins

Both paths converge at the same onboarding session. Only difference: pre-populated fields and which email template was sent.

### Dispatcher Sends Invite
1. Dispatcher opens carrier detail page (or creates new carrier with name/email/phone)
2. Clicks "Send Onboarding Invite"
3. System generates secure token, sends email + SMS with portal link
4. Carrier record transitions to `onboardingStatus: NOT_STARTED`

### Carrier Completes Onboarding
1. Carrier opens invite link -> portal validates token -> shows conversational interview
2. Phase 1 (Company): Business name, MC#, DOT#, EIN, contact info, factoring, fuel cards
3. Phase 2 (Equipment): Vehicle type multi-select -> type-specific compliance sub-questions -> add individual vehicles
4. Phase 3 (Drivers): Add drivers with pay info (if any besides carrier)
5. Phase 4 (Cost Analysis): 6 questions -> full-screen result card showing break-even RPM, min rate, expenses
6. Phase 5 (Lane Preferences): Home base, max days out, preferred lanes, states to avoid, freight prefs
7. Phase 6 (Documents): Sign dispatch agreement (canvas), upload COI + W-9 + carrier packet
8. Carrier sees completion screen -> "Application under review" message
9. Carrier record transitions to `onboardingStatus: COMPLETED`

### Conversational Interview UX

The interview works like TurboTax:
- One question at a time, large bold text, hint in grey
- Carrier answers -> answer collapses into a compact summary card in the thread above
- Next question fades in below
- Carrier can scroll up and click Edit on any previous answer
- **Sub-questions** reveal inline below the parent answer with colored left borders:
  - Blue: required compliance info
  - Green: optional info (can skip)
  - Red: compliance flag requiring attention
  - Grey: neutral follow-up
- Changing a parent answer clears sub-answers
- Auto-save fires after every single answer (debounced 500ms)

The interview has 6 phases (like TurboTax sections):
1. Company
2. Equipment
3. Drivers
4. Cost Analysis
5. Lane Preferences
6. Documents

### Dispatcher Approves/Rejects
1. Dispatcher sees pending carrier in dashboard queue or on carrier detail
2. Opens approval gate — sees all 6 phases of submitted data
3. Approves -> carrier status = ACTIVE, minimumRatePerMile activates in Load Intel, activation email/SMS sent
4. Rejects -> requires reason, rejection email/SMS sent to carrier

## Vehicle Type Branching

Four vehicle types with specific compliance rules:

### Semi Truck (Class 8 CDL)
- MC authority: REQUIRED
- DOT registration: REQUIRED
- Insurance minimums: $1,000,000 commercial auto, $100,000 cargo
- Sub-questions: MC#, DOT#

### Box Truck
- GVWR determines compliance:
  - < 10,000 lbs: green indicator, no DOT needed
  - 10,001-26,000 lbs: amber indicator, DOT optional (intrastate)
  - > 26,001 lbs: red indicator, DOT REQUIRED (federal), DOT# sub-question fades in immediately
- MC authority: OPTIONAL
- Insurance minimums: $300,000 commercial auto, $100,000 cargo

### Cargo Van (non-CDL)
- MC authority: OPTIONAL
- DOT: NOT REQUIRED
- Insurance minimums: $300,000 commercial auto
- Shows non-CDL regulatory callout card (LLC, business bank account, EIN, commercial auto rider — color-coded required/recommended)

### Personal Vehicle (courier/last-mile)
- MC: NOT REQUIRED, DOT: NOT REQUIRED
- Requires commercial auto rider on personal policy
- Insurance minimum: $300,000 commercial auto
- Shows non-CDL regulatory callout card
- Delivery types required (courier, last-mile, medical courier)

### Mixed Fleets
Show compliance sub-questions for each selected type in parallel within the same question card.

### GVWR Live Indicator
As carrier types weight, indicator changes reactively (green/amber/red) with threshold labels.

## Insurance Handling (Per Vehicle Type)

Every vehicle type shows an insurance block with 3 components:
1. **Minimum badge** — exact coverage amounts required for that vehicle type
2. **Monthly cost input** — carrier enters their insurance cost
3. **Confirmation checkbox** — carrier attests their policy meets minimums (creates legal record)

## Non-CDL Regulatory Callout

Cargo van and personal vehicle operators see an informational card:
- Commercial auto insurance rider (REQUIRED)
- LLC or business entity (RECOMMENDED)
- Business bank account for ACH settlements (RECOMMENDED)
- EIN for year-end 1099 (REQUIRED)
- Note: "Your dispatcher will help you get set up if anything is missing"
- This INFORMS without BLOCKING.

---

## Medical Courier Compliance

For personal vehicle carriers who select medical courier delivery type:
- Ask: "Do you transport pharmaceuticals?" (yes/no)
- If yes: "Do those include controlled substances?" (yes/no)
- That's ALL. A flag callout explains the dispatcher will schedule a compliance verification call.
- Full compliance questions (DEA, chain of custody, temp control) are handled in that call, NOT in the flow.

## Technical Context

### Existing Code to Reuse

- **`authenticateDriverToken.ts`** (dispatch-api) — Pattern for carrier portal token auth middleware
- **`calculateCpm.ts`** (dispatch-api/shared/scoring) — CPM calculation from expenses, used directly in cost analysis
- **`calculateMinBookRate.ts`** (dispatch-api/shared/scoring) — Min rate formula, used directly in cost analysis
- **`documentService.ts`** (dispatch-api/documents) — Presign/confirm/list flow, reuse for portal document endpoints
- **`eventMap.ts`** (dispatch-api/shared/messaging) — Extend with 4 new events
- **`notificationSubscriber.ts`** (dispatch-api/notifications) — Follow pattern for onboarding subscribers
- **`smsService.ts`** (dispatch-api/shared/notifications) — Twilio integration, ready to use
- **Form field components** (dispatch-ui/mocho/components/form-fields) — 32+ components for interview input types
- **Dual-slice Redux pattern** — Entity + page slice pattern from carrier feature

### Key Decisions

- **Separate `CarrierInviteToken` model** — Not reusing `LoadTrackingToken` because lifecycle differs (carrier-scoped, multi-session, 7-day expiry vs load-scoped, single-use)
- **`OnboardingSession.answers` as JSON** — Single JSON field keyed by question ID for auto-save simplicity. Each PUT upserts one answer.
- **Conversational form from day one** — No stepper. The interview is built as a one-question-at-a-time thread pattern from Phase 1. This avoids building throwaway stepper code.
- **Cost analysis reuses scoring utils** — Onboarding creates `TruckExpense` records exactly as the vehicle expense system does, so Load Intel scoring works without modification.
- **Signature stored as base64 on Document** — Simple storage, no external e-sign service in Phase 1.
- **E-SIGN consent fields on Carrier** — IP + user agent stored on carrier record (applies to dispatch agreement as a whole).
- **`minimumRatePerMile` on Carrier** — Persisted field (not just calculated) so Load Intel reads it directly without re-computing.

## Acceptance Criteria (End-to-End)

1. Dispatcher creates a carrier with name + email, clicks "Send Onboarding Invite" -> carrier receives email + SMS with portal link
2. Carrier opens portal link -> sees conversational interview -> completes all phases including document signing -> sees completion screen
3. Carrier closes browser mid-onboarding -> reopens link -> resumes at saved question with all answers intact
4. Cost analysis result card shows mathematically correct break-even RPM and minimum rate based on 6 inputs
5. Dispatcher sees carrier in pending queue -> opens approval gate -> sees complete profile -> approves -> carrier status = ACTIVE
6. After approval, carrier's `minimumRatePerMile` is available in Load Intelligence scoring (existing `scoreFleetUnit` uses it)
7. Rejected carrier receives email + SMS with rejection reason
8. Expired/revoked invite tokens show an error page, not the interview
9. Vehicle type branching enforces correct compliance rules (MC required for semi, GVWR > 26001 requires DOT for box trucks, etc.)
10. All 4 documents (dispatch agreement, insurance cert, W-9, carrier packet) must be signed/uploaded before submission
