# Load Board Production — Hardening + Dispatch Workflow

> Generated by /prd-refine on 2026-04-10
> Depends on: load-board-ingest (must be complete first)

## Problem

The MVP load board ingests and displays loads but lacks the production features needed for real dispatch operations: preference-based filtering, pagination across all Relay results, booking loads into the dispatch system, lane rate analytics, and infrastructure hardening for multi-org scale.

## Solution Overview

Harden the load board pipeline for production use: add preference filtering so dispatchers only see relevant loads, enable multi-page Relay fetching, add a Book action that promotes staged loads into real Load records, build lane rate analytics for pricing intelligence, archive raw snapshots to S3, and harden infrastructure (per-org rate limiting, Redis Sentinel, feed pagination).

## Capabilities

### Must Have (P0)
- Preference filtering on ingest: rate, equipment, no-go zones, duration, driver availability
- Book action: claim staged load → create real Load record in Postgres
- Pagination replay: extension fetches all pages from Relay (not just page 1)
- Per-org rate limiting on ingest and feed endpoints
- Feed pagination (cursor-based, 50 per page)
- Staleness UX: banner when data >90s old, empty state when extension disconnected

### Nice to Have (P1)
- Lane rate analytics (LaneRateSummary daily aggregation)
- S3 raw snapshot archival via RabbitMQ event
- Real DAT integration (replace mock fixture with live scraping)
- Content-hash dedup on extension (skip redundant API pushes)
- Redis Sentinel/Cluster for failover

### Book Flow
1. `POST /api/v1/load-board/:id/book`
2. Redis WATCH/MULTI atomic claim: check exists → SADD booked → SREM snapshot → DEL load
3. If load gone → 410 Gone
4. If already claimed → 409 Conflict
5. Return full load JSON → pre-fill Load creation form
6. Create real Load + Stops in Postgres via existing `createLoad` service

## Preference Filtering

Runs API-side during ingest. Extension sends all loads, API filters:

| Filter | Source | Check |
|--------|--------|-------|
| Min rate | `carrier.minimumRatePerMile` | `ratePerMile < min` → reject |
| Equipment | `driver.freightPreferences[]` | mapped type not in list → reject |
| No-go zones | `driver.noGoZones[]` | origin/dest state/city match → reject |
| Duration | `driver.maxTripDuration` | `totalDuration > max` → reject |
| Availability (LOCAL/REGIONAL) | `driver.weeklySchedule` | pickup day+time outside schedule → reject |
| Availability (OTR) | `driver.maxDaysOut` | trip extends beyond max days → reject |

### Filtering by Driver Type

| Driver Type | Availability Check |
|---|---|
| **LOCAL** | Pickup must fall within weeklySchedule for that day. Load must complete same day or within schedule. |
| **REGIONAL** | Same as LOCAL with wider radius tolerance. |
| **OTR** | Available 24/7 during out periods. maxDaysOut caps trip chain length. |

## Analytics

### Tier 1: Lane Rate Summaries (Postgres)
- In-memory aggregator updates running stats (min/max/avg/sum/count) per lane on each snapshot promotion
- Daily cron flushes aggregates → `LaneRateSummary` upsert
- Growth: ~18K rows/year/org. Scales to 200+ orgs.

### Tier 2: S3 Raw Snapshots
- `relay.snapshot.promoted` event → RabbitMQ handler → compress JSONL → upload to S3
- Path: `s3://hustle-analytics/snapshots/{orgId}/{date}/relay-{epoch}.jsonl.gz`
- ~$2/month at 200 orgs
- Queryable with Athena

## Pagination Replay (Extension)

Extension captures CSRF token + request body from original Relay search. Popup shows "Page 1 of 5 — 231 loads" with Next/Prev/Fetch All. Each page click replays `fetch('/api/loadboard/search')` in page context with incremented `nextItemToken`.

Epoch counter tracks page groups. API accumulates pages via `loadboard:pagination:{orgId}:{epoch}` hash. Snapshot promoted only when all pages arrive.

## Infrastructure Hardening

| Concern | Implementation |
|---|---|
| Per-org rate limiting | `rateLimiter` middleware with key = `req.user.organizationId`. Ingest: 5/min. Feed: 30/min. |
| Redis Sentinel | ioredis Sentinel config. Application code unchanged — config-only change. |
| Feed pagination | Sorted Set (`ZRANGEBYSCORE` with LIMIT) instead of Set. Map endpoint uses JSON.MGET for lightweight fields only. |
| Staleness detection | Snapshot set TTL 90s. Feed returns `stale: true` when snapshotAge > 45s. UI shows warning banner. |
| Content-hash dedup | Extension computes SHA-256 of response body. Skip POST if identical to previous. |
