# Production Refinement & Polish

> Generated by /prd-refine on 2026-03-25

## Problem

The application is approaching its first production push. A codebase audit identified 13 issues across UI polish, error handling, missing API data, and code organization that need resolution before launch. These range from invisible mobile UI elements to missing aggregate statistics that leave detail pages showing placeholder dashes.

## Solution Overview

A focused refinement pass addressing three areas:
1. **UI polish** — Fix broken mobile header, replace loading spinners with skeletons, theme consistency
2. **Data completeness** — Add entity stats endpoints, wire missing KPI fields, expand invoice includes
3. **Code quality** — Consolidate duplicated components, add proper 403 handling, support non-CDL drivers

All 13 tasks are P0 — required before production.

## User Flows

### Mobile Header (Task 1)
1. User opens app on mobile device (< 1266px)
2. Appbar shows toggle button (white icon, no background) on left, logo on right
3. User taps toggle — sidebar drawer opens
4. Toggle icon changes to collapse variant

### 403 Error Handling (Task 2)
1. User performs action they lack permission for (e.g., non-admin deletes invoice)
2. API returns 403 with error message
3. Toast/snackbar appears with the message ("Only ADMIN can delete invoices")
4. User stays on current page, no redirect
5. **Exception:** If 403 message is "Organization is suspended or inactive", clear tokens and redirect to `/login`

### Pickup Date Column (Task 3)
1. User opens Dispatch Board
2. LoadTable shows "Pickup" column with date from first stop's appointmentDate
3. No "Created" column exists

### CarrierKPI Stats (Task 4)
1. User opens carrier detail page
2. UI renders driverCount and vehicleCount from detail response immediately
3. UI fetches `GET /carriers/:id/stats` for lifetimeRevenue and loadCount
4. KPI cards update with real values (no "—" placeholders)

### Entity Stats Pattern (Tasks 10-12)
1. User opens entity detail page (contact, customer, or place)
2. Detail data loads from existing endpoint
3. Stats section shows loading skeleton
4. Frontend fetches `GET /:entity/:id/stats`
5. Stats populate with real aggregate values

### Save Contact After Load Creation (Task 7)
1. User creates a load with a new contact (typed in, not from autocomplete)
2. Load is created successfully
3. Prompt/dialog appears: "Save [contact name] as a new contact?"
4. User confirms — contact is saved to contact database
5. User declines — contact exists only on the load

## Technical Context

### Existing Code to Reuse

- `ListSkeleton`, `FormSkeleton` (`dispatch-ui`) — existing skeleton loader components for task 6
- `EditDrawer` at `src/components/EditDrawer/` (`dispatch-ui`) — already exists as shared component, needs carrier duplicate removed (task 9)
- `loadTransformer` origin stop derivation (`dispatch-api`) — already computes origin from first stop, reuse for pickupDate (task 3)
- `dashboardQueryPrisma` aggregate patterns (`dispatch-api`) — follow same `_sum`, `_count`, `_avg` Prisma patterns for stats endpoints (tasks 10-12)
- `Prisma _count` pattern on carrier repository (`dispatch-api`) — already used for driverCount/vehicleCount, model for simple counts
- Toast/snackbar infrastructure (`dispatch-ui`) — existing notification system for 403 error messages (task 2)
- `ConfirmDialog` (`dispatch-ui`) — reuse for "save contact?" prompt (task 7)

### Key Decisions

- **Stats endpoints are separate from detail** — `GET /:entity/:id/stats` pattern. Keeps detail responses fast, stats are opt-in. Follows dashboard module precedent.
- **Carrier uses hybrid approach** — driverCount/vehicleCount stay embedded (cheap `_count`), lifetimeRevenue/loadCount go to stats endpoint (cross-entity aggregation).
- **403 handling is toast, not redirect** — Most 403s are permission denials for logged-in users. Only org-suspended triggers redirect.
- **LoadTable replaces createdAt entirely** — No dual-column approach. Dispatchers need pickup date, not record creation date.
- **MembershipRole enum excluded** — Bare string `role` on Membership is by design, not a bug.
- **Driver licenseType is an enum** — `CDL_A`, `CDL_B`, `NON_CDL`. CDL fields become optional/nullable.
