## Context

Track 7 covers driver pay configuration, location updates, and weekly availability + overrides. Codebase audit shows the track is **~95% already built** by prior work (likely Track 3 / Track 8+9 dependencies built it incidentally). This plan therefore reframes Track 7 as:

1. **Verification pass** — confirm what exists matches the spec.
2. **One substantive change** — make `payType` + `payRate` **required** at driver creation and **backfill** every existing driver to `PERCENTAGE / 30%` so the column can become `NOT NULL`.
3. **Documentation** — update `mvp-plan.md` Track 7 status and flag deferrals.

Why this matters: the financial pipeline (Track 8+9) consumes `payType`/`payRate` to compute `DRIVER_PAY` settlement line items via `computeDriverPay()`. Drivers with null pay silently produce $0 driver pay on settlement, which is exactly the kind of money bug we want eliminated before the real-dispatcher trial (V.TRIAL.1).

## Solution Overview

### Change 1 — Make payType + payRate required (NEW work)

**Backend (`hussle-app-dispatch-api/`):**
- Update `validators/driverValidators.ts` (driver create + update schemas): `payType` becomes `.required()`, `payRate` becomes `.required().min(0)`.
- Update `services/driverService.ts` create path: remove any "if payType set" branching; assume always present.
- **Prisma migration** `prisma/migrations/<timestamp>_require_driver_pay/migration.sql`:
  1. `UPDATE "Driver" SET "payType" = 'PERCENTAGE', "payRate" = 30 WHERE "payType" IS NULL OR "payRate" IS NULL;`
  2. `ALTER TABLE "Driver" ALTER COLUMN "payType" SET NOT NULL;`
  3. `ALTER TABLE "Driver" ALTER COLUMN "payRate" SET NOT NULL;`
- Update `prisma/schema.prisma` Driver model: drop `?` from `payType` and `payRate`.
- Regenerate Prisma client; fix any TS errors from removed nullability across the codebase (search `payType ?? `, `payRate ?? `, `if (driver.payType)`).

**Frontend (`hussle-app-dispatch-ui/`):**
- Update `features/driver/validators/driverInfoSchema.ts`: `payType` `.required('Pay type is required')`, `payRate` `.required('Pay rate is required').min(0)` (drop the `.when()` conditional).
- Update `DriverFormDrawer/index.tsx`: drop the "visible only if payType set" gate on `payRate`; render both unconditionally; remove the empty-string-to-null coercion lines (~31-36).
- Update default form values: `payType: 'PERCENTAGE'`, `payRate: 30` for new drivers (matches backfill default; dispatcher can change before save).
- Update tests in `DriverFormDrawer/__tests__/` for new required validation.

## Key Decisions

- **Pay type + rate required at creation** — eliminates silent $0 driver-pay settlements. (User-confirmed.)
- **Backfill default = `PERCENTAGE` / 30%** — consistent with industry-standard owner-operator-style split. Dispatcher can edit per-driver afterwards. (User-confirmed.)
- **Reuse general PATCH for location** — the existing endpoint already auto-geocodes. A dedicated `/location` endpoint would be cosmetic. (User-confirmed.)
- **SMS scheduler does NOT honor driver availability** — deferred post-MVP. Driver schedule remains informational/dispatcher-facing only. (User-confirmed; matches Track 3 "no quiet hours" decision.)
- **No new schedule UI** — existing `DriverWeeklyScheduleDrawer` + `DriverScheduleOverrideDrawer` cover the spec.

## Acceptance Criteria

1. `Driver.payType` and `Driver.payRate` columns are `NOT NULL` in the database after migration.
2. Every pre-existing `Driver` row with previously-null pay has `payType = 'PERCENTAGE'` and `payRate = 30`.
3. `POST /drivers` returns 400 if `payType` or `payRate` is omitted.
4. `PATCH /drivers/:id` rejects setting `payType` or `payRate` to null.
5. `DriverFormDrawer` shows both fields unconditionally, marks them required (asterisk), and defaults new-driver values to PERCENTAGE/30.
6. Yup validation in `driverInfoSchema` blocks submit when either field is empty.
7. Driver detail page → weekly-schedule drawer opens, saves a Mon–Sun schedule, persists via `PUT /drivers/:driverId/availability/weekly`, reloads correctly.
8. Driver detail page → override drawer creates a date-typed OFF override, persists, lists, deletes.
9. Driver location drawer save updates `currentCity`/`currentState` and the API populates `currentLatitude`/`currentLongitude` via geocode.
10. `mvp-plan.md` Track 7 reflects done status with the refined-scope note.
11. `cd hussle-app-dispatch-api && npm run validate` exits 0.
12. `cd hussle-app-dispatch-ui && npm run validate` exits 0.
