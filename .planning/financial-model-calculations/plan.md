# Financial Model — Phase 4+5: Calculation Wiring, Transformers, and Recalculation

> Generated by /prd-refine on 2026-04-05
> Design doc: `hussle-app-dispatch-api/docs/designs/financial-model-redesign.md` (Sections 6–9, 13–14, Appendix A1–A2, B1–B4)
> Depends on: `financial-model-schema` (complete — schema, calculation engine, tests, data migration all done)
> Depends on: `financial-model-bugfixes` (complete — updateLoad recalc, revenue metrics, weekly gross)

## Problem

The calculation engine (`calculateLoadFinancials`) is complete and tested, but several downstream integrations are missing:

1. **vehicleCpm is never passed** — `calculateAndPersistFinancials` leaves it undefined, so `estimatedCost` is always null. The vehicle's RecurringExpense data exists but isn't queried at calculation time.

2. **Dispatcher commission is never passed** — `DispatcherProfile` model exists in the schema but no service reads it. `dispatcherComm` and `companyNet` are always null.

3. **Accessorial changes don't recalculate load financials** — the `accessorialSyncSubscriber` only updates invoice totals. When accessorials change post-dispatch, `companyMargin`, `carrierPayout`, `driverPay`, and `dispatcherComm` go stale.

4. **API responses lack derived financial fields** — `loadTransformer` returns raw stored fields but doesn't compute `carrierRpm`, `companyNet`, `marginPercent`, or `estimatedNetEarnings`.

5. **No post-dispatch freeze enforcement** — the design doc specifies which fields freeze after DISPATCHED, but this isn't enforced in the recalculation path.

6. **estimatedHours not auto-derived** — PER_HOUR drivers need `estimatedHours` derived from stop appointments when not manually set.

## Solution Overview

Wire the remaining inputs into `calculateAndPersistFinancials`, add a financial recalculation subscriber for accessorial events, update transformers with derived fields, and enforce freeze rules.

## Capabilities

### Must Have (P0)

- **Wire vehicleCpm into financial calculation** — query RecurringExpense for the load's vehicle, compute estimated CPM, pass to `calculateLoadFinancials` so `estimatedCost` populates
- **Wire dispatcher commission** — look up `DispatcherProfile` for the load's `dispatcherUserId`, pass commission config to `calculateLoadFinancials` so `dispatcherComm` and `companyNet` populate
- **Accessorial-driven financial recalculation** — new subscriber listens to `accessorial.created`, `accessorial.updated`, `accessorial.deleted` events and calls `calculateAndPersistFinancials` for the affected load
- **Transformer derived fields** — compute `carrierRpm`, `companyNet`, `marginPercent`, `estimatedNetEarnings` in `loadTransformer` from stored fields
- **Expose new financial fields in load detail response** — `carrierPayout`, `companyMargin`, `driverPay`, `estimatedCost`, `dispatcherComm` + derived fields
- **Expose key financial fields in load list response** — `companyMargin`, `carrierPayout`, `companyNet`

### Nice to Have (P1)

- **estimatedHours auto-derivation** — when driver is PER_HOUR and `estimatedHours` is not set, derive from first PICKUP and last DELIVERY `appointmentStart` times
- **Freeze rules enforcement** — block `customerRate` changes after DISPATCHED in the recalculation path (updateLoad guard may already handle this, but accessorial-triggered recalc needs to skip frozen fields)

## User Flows

### Flow 1: Load Created/Assigned — Full Financial Calculation
1. Dispatcher creates or assigns a load with carrier + customerRate
2. `calculateAndPersistFinancials` fires (existing)
3. **NEW:** Queries vehicle's RecurringExpense to compute vehicleCpm
4. **NEW:** Queries DispatcherProfile for the load's dispatcherUserId (if set)
5. Passes vehicleCpm and dispatcherComm config to `calculateLoadFinancials`
6. All financial fields populated including `estimatedCost`, `dispatcherComm`, `companyNet`
7. GET /loads/:id returns full financial detail with derived fields

### Flow 2: Accessorial Added Post-Dispatch
1. Dispatcher adds a $200 detention charge to a dispatched load
2. `accessorial.created` event published (existing)
3. **NEW:** `financialRecalcSubscriber` catches the event
4. Fetches the load with relations
5. Calls `calculateAndPersistFinancials` — respects freeze rules:
   - `customerRate`, `ratePerMile`, `estimatedCost` stay frozen
   - `companyMargin`, `carrierPayout`, `driverPay`, `dispatcherComm` recalculate from new accessorial total
6. Invoice totals also update (existing subscriber)

### Flow 3: Dispatcher Assigned to Load
1. Dispatcher sets `dispatcherUserId` on a load (via updateLoad)
2. Financial recalculation triggers (existing updateLoad flow)
3. **NEW:** DispatcherProfile looked up → commission config passed to calculation
4. `dispatcherComm` and `companyNet` now populated

## Data Requirements

No new schema changes. All fields already exist from `financial-model-schema`:
- Load: `carrierPayout`, `companyMargin`, `driverPay`, `estimatedCost`, `dispatcherComm`, `dispatcherUserId`
- DispatcherProfile: `commissionType`, `commissionRate` (linked via Membership → User)
- RecurringExpense: `amount`, `vehicleId` (for CPM calculation)

## API/Interface Changes

### Load Detail Response (updated transformer)

Add to existing `LoadDetailResponse`:

```typescript
// Stored fields (now included in response)
carrierPayout: string | null;
companyMargin: string | null;
driverPay: string | null;
estimatedHours: string | null;
estimatedCost: string | null;
dispatcherComm: string | null;

// Derived in transformer (not stored)
carrierRpm: string | null;        // carrierPayout / loadedMiles
companyNet: string | null;        // companyMargin - dispatcherComm
marginPercent: string | null;     // companyMargin / gross × 100
estimatedNetEarnings: string | null; // carrierPayout - estimatedCost
```

### Load List Response (updated transformer)

Add: `companyMargin`, `carrierPayout`, `companyNet` (derived).

## Technical Context

### Existing Code to Reuse

- `calculateAndPersistFinancials` (`src/loads/services/calculateFinancials.ts`) — expand deps to accept CPM query port and dispatcher profile query port
- `calculateLoadFinancials` (`src/shared/financials.ts`) — already accepts vehicleCpm and dispatcherComm inputs, just needs them wired
- `calculateCpm` (`src/shared/scoring/calculateCpm.ts`) — pure function, takes expense items and returns CPM number
- `accessorialSyncSubscriber` pattern (`src/invoices/services/accessorialSyncSubscriber.ts`) — follow same event handler pattern for financial recalc subscriber
- Event map (`src/shared/messaging/eventMap.ts`) — accessorial events already defined
- Composition root pattern (`src/loads/compositionRoot.ts`) — wire new dependencies here

### Key Decisions

- **vehicleCpm sourced from RecurringExpense (estimated CPM)** — actual CPM from Expense table requires the expense CRUD module (separate plan). RecurringExpense exists from schema migration and TruckExpense data migration. Use estimated CPM until actual expense data is available.
- **DispatcherProfile lookup via a query port** — injected into `calculateAndPersistFinancials` deps, not imported directly. Follows the cross-module read pattern from CLAUDE.md.
- **Derived fields computed in transformer, not stored** — `carrierRpm`, `companyNet`, `marginPercent`, `estimatedNetEarnings` are calculated on read. Avoids denormalization and staleness.
- **Financial recalc subscriber is separate from invoice sync subscriber** — different concern (load financials vs invoice totals). Both listen to same events.
- **Freeze rules applied inside recalculation** — when recalculating post-dispatch, only recompute fields that are allowed to change. `customerRate` and `estimatedCost` stay frozen. `companyMargin`, `carrierPayout`, `driverPay`, `dispatcherComm` recalculate.
- **OWNER_OPERATOR still excluded** — continues to throw `OwnerOperatorNotSupportedError` (decision from schema plan).

## Acceptance Criteria

### CPM Wiring
- [ ] `calculateAndPersistFinancials` queries RecurringExpense data for the load's vehicle
- [ ] vehicleCpm is computed and passed to `calculateLoadFinancials`
- [ ] `estimatedCost` populates on loads where vehicle has RecurringExpense data and totalMiles is set
- [ ] `estimatedCost` is null when no RecurringExpense data exists for the vehicle
- [ ] `estimatedCost` is null when totalMiles is null

### Dispatcher Commission Wiring
- [ ] `calculateAndPersistFinancials` looks up DispatcherProfile for the load's dispatcherUserId
- [ ] Commission config (type + rate) passed to `calculateLoadFinancials`
- [ ] `dispatcherComm` populates on loads where dispatcherUserId is set and DispatcherProfile exists
- [ ] `dispatcherComm` is null when dispatcherUserId is null
- [ ] `companyNet` = companyMargin - dispatcherComm when both are non-null

### Accessorial-Driven Recalculation
- [ ] New subscriber listens to `accessorial.created`, `accessorial.updated`, `accessorial.deleted`
- [ ] Subscriber calls `calculateAndPersistFinancials` for the affected load
- [ ] Adding an accessorial to a dispatched load recalculates `companyMargin`, `carrierPayout`, `driverPay`, `dispatcherComm`
- [ ] `customerRate` and `estimatedCost` are NOT changed by accessorial recalculation (freeze rules)
- [ ] Both subscribers fire independently (invoice sync + financial recalc)

### Transformer Updates
- [ ] Load detail response includes stored fields: `carrierPayout`, `companyMargin`, `driverPay`, `estimatedHours`, `estimatedCost`, `dispatcherComm`
- [ ] Load detail response includes derived fields: `carrierRpm`, `companyNet`, `marginPercent`, `estimatedNetEarnings`
- [ ] `carrierRpm` = `carrierPayout / loadedMiles` (null if either null)
- [ ] `companyNet` = `companyMargin - dispatcherComm` (null if either null)
- [ ] `marginPercent` = `companyMargin / (customerRate + accessorials) × 100` (null if companyMargin null)
- [ ] `estimatedNetEarnings` = `carrierPayout - estimatedCost` (null if either null)
- [ ] Load list response includes `companyMargin`, `carrierPayout`, `companyNet`
- [ ] All derived fields use Decimal.js with banker's rounding to 2 decimal places

### estimatedHours Auto-Derivation (P1)
- [ ] When driver payType is PER_HOUR and estimatedHours is not set, derive from first PICKUP appointmentStart to last DELIVERY appointmentStart
- [ ] If stop times are not available, estimatedHours stays null
