# document-signing — PRD

> Generated by /prd-refine on 2026-05-14
> Feature 2 of 3 in the MACHO carrier-portal-rebuild sequence (`fmcsa-integration` ✅ → **document-signing** → `carrier-portal-v2`).

## Summary

Two new modules in `hussle-app-dispatch-api/`:

1. **`src/shared/signatures/`** — provider-agnostic e-signature module behind a port + adapter. First-class `MockSignatureProvider` for dev/test; real `DocuSealProvider` for staging/prod. Mirrors the `src/shared/fmcsa/` shape exactly.
2. **`src/agreements/`** — feature module owning the `Agreement` Prisma entity, its lifecycle (`Draft → Pending → Signed | Voided`), the dispatcher-facing HTTP endpoints, the HMAC-verified DocuSeal webhook receiver, the post-signing artifact subscriber, and the missed-webhook watchdog.

Initial consumer is the **dispatcher** (manual trigger endpoint — "send dispatch agreement to this carrier"); the **carrier-portal-v2** (Feature 3) will consume the same module mid-flow.

## Why two modules

- **`src/shared/signatures/`** is e-signature plumbing — port, adapter, mock, template rendering. Same shape as FMCSA: usable by any feature that needs a document signed (dispatch agreement today; broker MSAs, NDAs, accessorial waivers tomorrow).
- **`src/agreements/`** owns the *domain entity* — the Agreement row, its state machine, the audit trail, the S3 artifacts. Domain ownership ≠ provider plumbing.

## Capabilities

### Must Have (P0)

#### `src/shared/signatures/` — provider plumbing

- **`SignatureProviderPort` interface** exposing:
  - `createSubmission(input: CreateSubmissionInput): Promise<SubmissionRef>` — returns `{ providerSubmissionId, embedUrl, expiresAt }`.
  - `getSubmission(providerSubmissionId: string): Promise<SubmissionStatus>` — for watchdog reconciliation.
  - `voidSubmission(providerSubmissionId: string): Promise<void>`.
  - `fetchSignedArtifacts(providerSubmissionId: string): Promise<{ signedPdf: Buffer; auditCertificate: Buffer }>` — called after `agreement.signed`.
- **`SignatureSubmission` / `SubmissionStatus` types** modeling the response: `providerSubmissionId`, `embedUrl`, `expiresAt`, discriminated `status: 'pending' | 'signed' | 'declined' | 'voided' | 'expired'`, `signerEvents` (timestamped: viewed/signed/IP/UA), `raw` (provider payload for audit).
- **`MockSignatureProvider`** — first-class, deterministic, configurable failure modes (`timeout`, `not_found`, `rate_limit`, `decline`). Same inputs → same `providerSubmissionId`. Embed URL points to a stub UI under `/dev/sign/:submissionId` that simulates the signing UX and lets dev POST to a local "webhook" emulator endpoint.
- **`DocuSealProvider`** — real HTTP adapter against self-hosted DocuSeal v1.x. Sends HTML directly (DocuSeal handles HTML→PDF). Uses text-tag field anchoring in templates so signer/date fields don't break when legal edits copy. Stubbed in v1 *only* for the safer-web parallel — actual DocuSeal HTTP calls land in this PR. Retry with exponential backoff (3 attempts, 1s / 5s / 30s) on 5xx and timeouts. 4xx surfaces as `error` immediately.
- **`signatureService` factory** (`createSignatureService`) wrapping the port with:
  - Caller-supplied `correlationId` opt (UUID generated if absent) for event traceability.
  - Structured logging via injected `LoggerPort`.
  - Observability events: `signature.submission.created`, `signature.submission.failed`. No caching — submissions are unique per agreement.
- **`renderDispatchAgreement`** — pure function rendering the React Email template `agreementTemplates/dispatchAgreement.tsx` to HTML with variables (`carrierLegalName`, `carrierMcNumber`, `carrierDotNumber`, `orgName`, `effectiveDate`). Template uses DocuSeal text-tag anchors (`{{signer1.signature}}`, `{{signer1.date}}`) so field placement is encoded in copy, not template positions.
- **Composition root**: `createSignatureModule({ eventBus, logger, env })` returns `{ service, provider }`. Provider selection via `env.SIGNATURE_PROVIDER: 'mock' | 'docuseal'` (default `'mock'` in dev/test).
- **Unit tests**: port contract test (any provider must satisfy), mock determinism, retry behavior, event emission, HTML render snapshot.

#### `src/agreements/` — domain entity + lifecycle

- **`Agreement` Prisma model** (per tech design §4.6):
  ```
  id (uuid)               organizationId (FK Organization)
  carrierId (FK Carrier)  templateKey (enum: DISPATCH_AGREEMENT)
  variables (Json)        providerSubmissionId (unique nullable)
  status (enum)           — DRAFT → PENDING → SIGNED | VOIDED | EXPIRED
  embedUrl (nullable)     embedUrlExpiresAt (nullable)
  signedPdfS3Key          auditCertificateS3Key
  signedPdfSha256         signedAt
  voidedAt / voidReason
  createdAt / createdByUserId / updatedAt
  ```
  Indexes: `(providerSubmissionId)` unique for webhook routing, `(organizationId, carrierId, status)` for dispatcher list queries.

- **`AgreementRepoPort`** with `create`, `findById`, `findByProviderSubmissionId`, `findManyByCarrier`, `update`, `findStaleInProgress(olderThanMin)` (watchdog).

- **Services** (`{ data, events }` return shape, no Prisma imports):
  - `requestAgreement(input, deps)` — Dispatcher hits "send agreement". Service: render template, call `signatureService.createSubmission`, persist Agreement row (`status=PENDING`, store `providerSubmissionId` + `embedUrl`), emit `agreement.generated`. Returns `{ agreement }`.
  - `finalizeAgreement(input, deps)` — Called from `agreement.signed` subscriber. Idempotent: if already SIGNED, returns no-op. Fetches signed PDF + audit cert via `signatureService.fetchSignedArtifacts`, computes SHA-256, writes both to S3 under `orgs/{orgId}/carriers/{carrierId}/agreements/{agreementId}/`, updates Agreement to SIGNED, emits `agreement.finalized`.
  - `voidAgreement(input, deps)` — Dispatcher voids a pending agreement. Calls `signatureService.voidSubmission`, updates Agreement, emits `agreement.voided`.

- **HTTP endpoints** (dispatcher-auth, `requireRole([ADMIN, DISPATCHER])`):
  - `POST /api/v1/agreements` — body `{ carrierId, templateKey }`. Returns `201 { agreement: { id, status, embedUrl, embedUrlExpiresAt } }`. Embed URL is what the dispatcher pastes to the carrier (or the v2 portal opens in iframe).
  - `GET /api/v1/agreements/:id` — returns current agreement state including artifact URLs (presigned, 15-min TTL) once SIGNED.
  - `GET /api/v1/agreements?carrierId=…&status=…` — list for dispatcher dashboard.
  - `POST /api/v1/agreements/:id/void` — dispatcher voids.

- **DocuSeal webhook receiver** (`POST /webhooks/docuseal`, no `/api/v1`, no auth — public, HMAC-verified):
  - `verifyDocusealHmac` middleware reads `X-Docuseal-Signature` header, computes HMAC-SHA256 of raw body using `DOCUSEAL_WEBHOOK_SECRET`, compares via `crypto.timingSafeEqual`. Rejects on mismatch with 401.
  - Controller translates DocuSeal event types → domain events: `form.completed` → `agreement.signed`; `form.declined` → `agreement.declined`; `form.expired` → `agreement.expired`. Returns 200 immediately (idempotent, replay-safe — checks current Agreement status before emitting).
  - Replay protection: webhook handler is idempotent on `providerSubmissionId + targetStatus` — if Agreement already SIGNED, no-op.

- **`agreementSignedSubscriber`** (RabbitMQ subscriber on `agreement.signed`):
  - Idempotent. Pulls Agreement by `providerSubmissionId`, calls `finalizeAgreement`. If repeated, finalizeAgreement returns no-op.
  - Failures land in DLQ after retry budget exhausted (existing subscriber retry pattern).

- **`signedAgreementWatchdog`** (`node-cron`, runs every 5 minutes):
  - Scans Agreements where `status=PENDING AND updatedAt < now() - 10min`.
  - For each: calls `signatureProvider.getSubmission(providerSubmissionId)`. If DocuSeal reports `signed`, re-publishes `agreement.signed` (the subscriber's idempotency makes this safe).
  - If DocuSeal reports `voided` / `expired`, transitions the Agreement accordingly.
  - Started as side-effect from `compositionRoot.initializeWatchdogs()` in `src/app.ts`.

- **Observability events** (extend `EventMap`):
  - `agreement.generated` — `{ agreementId, organizationId, carrierId, templateKey, providerSubmissionId, correlationId }`
  - `agreement.signed` — `{ agreementId, organizationId, carrierId, providerSubmissionId, signedAt, correlationId }`
  - `agreement.declined` — `{ agreementId, organizationId, carrierId, providerSubmissionId, declinedAt }`
  - `agreement.expired` — `{ agreementId, organizationId, carrierId, providerSubmissionId, expiredAt }`
  - `agreement.voided` — `{ agreementId, organizationId, carrierId, voidedAt, voidReason, voidedByUserId }`
  - `agreement.finalized` — `{ agreementId, organizationId, carrierId, signedPdfS3Key, auditCertificateS3Key, signedPdfSha256 }`
  - `signature.submission.created` — `{ correlationId, providerSubmissionId, templateKey }`
  - `signature.submission.failed` — `{ correlationId, templateKey, reason: 'timeout' | 'rate_limit' | 'provider_error' }`

- **Dispatcher dispatch agreement template** — `agreementTemplates/dispatchAgreement.tsx`. Single canonical React Email component. Variables: carrier legal name, MC#, DOT#, org name, effective date. DocuSeal text-tag anchors for the carrier-signature and date fields. Body copy is a placeholder draft for v1; legal can iterate without code changes by editing the TSX.

## API / Interface Changes

### New TypeScript surface

```typescript
// src/shared/signatures/types.ts
interface CreateSubmissionInput {
  templateKey: 'DISPATCH_AGREEMENT';
  variables: Record<string, string>;
  signer: { name: string; email: string };
  metadata?: Record<string, string>;     // forwarded to provider for callback lookups
}

interface SubmissionRef {
  providerSubmissionId: string;
  embedUrl: string;
  expiresAt: Date;
}

type SubmissionStatus =
  | { status: 'pending'; providerSubmissionId: string }
  | { status: 'signed'; providerSubmissionId: string; signedAt: Date }
  | { status: 'declined'; providerSubmissionId: string; declinedAt: Date }
  | { status: 'voided'; providerSubmissionId: string; voidedAt: Date }
  | { status: 'expired'; providerSubmissionId: string; expiredAt: Date };

// src/shared/signatures/signatureProviderPort.ts
interface SignatureProviderPort {
  createSubmission(input: CreateSubmissionInput): Promise<SubmissionRef>;
  getSubmission(providerSubmissionId: string): Promise<SubmissionStatus>;
  voidSubmission(providerSubmissionId: string): Promise<void>;
  fetchSignedArtifacts(
    providerSubmissionId: string
  ): Promise<{ signedPdf: Buffer; auditCertificate: Buffer }>;
}

// src/shared/signatures/signatureService.ts
interface SignatureServiceOpts {
  correlationId?: string;
}

interface SignatureService {
  createSubmission(
    input: CreateSubmissionInput,
    opts?: SignatureServiceOpts
  ): Promise<SubmissionRef>;
  getSubmission(providerSubmissionId: string): Promise<SubmissionStatus>;
  voidSubmission(providerSubmissionId: string): Promise<void>;
  fetchSignedArtifacts(
    providerSubmissionId: string
  ): Promise<{ signedPdf: Buffer; auditCertificate: Buffer }>;
}
```

## Technical Context

### Existing patterns to reuse

- **`src/shared/fmcsa/`** — exact template for `src/shared/signatures/`. Port + adapter + mock + service factory + composition root. Same file layout, same naming, same test patterns.
- **`src/notifications/services/notificationSubscriber.ts`** — RabbitMQ subscriber template for `agreementSignedSubscriber`.
- **`src/settlements/services/settlementCronJob.ts`** — `node-cron` job pattern (`start / stop / runNow` interface) for `signedAgreementWatchdog`.
- **`src/shared/messaging/rabbitMqEventBus.ts`** — typed `EventMap` pub/sub. Add 8 events.
- **`src/shared/emails/documentUploaded/DocumentUploadedEmail.tsx`** + matching `renderDocumentUploadedEmail.ts` — React Email + renderer pattern for `dispatchAgreement.tsx`.
- **`src/shared/storage/index.ts`** — storage backend abstraction (S3 in prod, local in dev) for signed PDF + audit certificate persistence.
- **`src/shared/utils/logger.ts`** + **`src/shared/messaging/eventBus.ts`** — injected ports.
- **`src/config/env.ts`** — `FMCSA_PROVIDER` / `STORAGE_BACKEND` / `SMS_BACKEND` is the established backend-selection pattern. Follow it.
- **`prisma/schema.prisma:1033-1066` (Document model)** — schema shape reference for `Agreement` (org-scoped, indexed, JSON metadata, S3 key columns, status enum).

### Key decisions (locked)

- **DocuSeal OSS self-host** — accept AGPL implications for internal use; defer Pro-tier licensing question until redistribution / white-label is needed.
- **Two-module split** — `src/shared/signatures/` (provider plumbing, reusable) vs. `src/agreements/` (domain entity). Don't bury Agreement persistence inside the shared module.
- **Mock as a first-class provider** — `MockSignatureProvider` is the dev default. Local docker DocuSeal is opt-in via `SIGNATURE_PROVIDER=docuseal`. Tests use mock.
- **HTML template route, not pre-rendered PDF** — DocuSeal handles HTML→PDF. Single source of truth (React TSX). Migrate to Puppeteer-rendered PDF only if typography fidelity becomes a problem (tech design §13.2).
- **Single hardcoded template for v1** — `DISPATCH_AGREEMENT`. DB-stored templates with versioning is a follow-on once we have ≥3 templates.
- **New `Agreement` model, not extending `Document`** — typed lifecycle, dedicated indexes for webhook routing (`providerSubmissionId` unique), separate S3 path conventions per tech design §7.4.
- **Webhook public endpoint with HMAC** — `/webhooks/docuseal` mounted outside `/api/v1`, no JWT auth, signature-verified per request. Idempotent on `(providerSubmissionId, targetStatus)`.
- **Watchdog as belt-and-suspenders** — webhooks are primary; node-cron watchdog reconciles missed webhooks every 5 minutes. Without the watchdog, a dropped webhook strands the agreement in PENDING forever.
- **Service-level return contract** — `requestAgreement / finalizeAgreement / voidAgreement` return `ServiceResult<Agreement>` with events; controllers dispatch. No service writes to RabbitMQ directly.
- **Idempotency everywhere** — webhook handler, finalize service, subscriber, watchdog republish. RabbitMQ may redeliver; DocuSeal may re-emit; the watchdog may re-publish. All paths must be safe.
- **Capability + dispatcher manual trigger in scope; no portal integration** — Feature 3 wires the embed URL into the conversational flow. This PR ships the *capability* and a dispatcher-side trigger to prove the pipe end-to-end.
- **Staging deploy in scope** — local docker-compose + staging Dokploy/Terraform config land together. Otherwise we can't validate the real DocuSeal integration before Feature 3.
- **No EIN in Agreement payloads (v1)** — dispatch agreement variables limited to name / MC# / DOT# / org / date. EIN encryption at rest is a separate concern on the Carrier model.

### Risks

| Risk | Mitigation |
|---|---|
| DocuSeal HTML/CSS support breaks template rendering | Snapshot test on rendered HTML; preview in local DocuSeal during dev; fall back to Puppeteer pre-render if blocked. |
| Webhook delivery dropped silently | `signedAgreementWatchdog` reconciles every 5 minutes against DocuSeal `getSubmission`. |
| HMAC secret leaks via logs | Never log raw request bodies on `/webhooks/docuseal`. Logger redaction list adds `DOCUSEAL_WEBHOOK_SECRET` and `X-Docuseal-Signature`. |
| Replay attack on webhook | HMAC verification + idempotent state-machine check (already SIGNED → no-op). |
| Agreement persistence diverges from DocuSeal truth | Watchdog reconciliation; provider is authoritative on signed-state. |
| AGPL exposure | Self-host on internal infra only — no embedding in product distributed to third parties. Documented in CONCERNS.md. |

## Acceptance Criteria

1. **`npm run validate` passes** in `hussle-app-dispatch-api/` (lint + lint:deps + check-ts + test).
2. **`MockSignatureProvider.createSubmission`** with the same input returns the same `providerSubmissionId` deterministically; configurable failure modes verified by tests.
3. **`POST /api/v1/agreements`** with valid `{ carrierId, templateKey: 'DISPATCH_AGREEMENT' }` and dispatcher auth returns `201` with a `PENDING` agreement carrying an `embedUrl` and `embedUrlExpiresAt`. Persisted Agreement row has `providerSubmissionId`.
4. **`agreement.generated`** event emits on successful `requestAgreement` with the dispatcher's `correlationId` (or a service-generated UUID).
5. **`POST /webhooks/docuseal`** with a DocuSeal `form.completed` payload + valid HMAC signature transitions the Agreement to `SIGNED`, fetches signed PDF + audit certificate, persists them to storage, records SHA-256 of the signed PDF, and emits `agreement.signed` + `agreement.finalized`.
6. **Webhook HMAC verification rejects** payloads with invalid signature (`401`), missing signature header (`401`), or tampered body (`401`). Verified via integration test.
7. **Webhook is idempotent**: replaying the same `form.completed` payload twice produces exactly one `SIGNED` transition and no duplicate artifact writes.
8. **`signedAgreementWatchdog`** detects an Agreement stuck in `PENDING` whose DocuSeal submission has moved to `signed`, and re-publishes `agreement.signed`. The subscriber's idempotency prevents duplicate finalization. Verified via integration test.
9. **`POST /api/v1/agreements/:id/void`** transitions a `PENDING` agreement to `VOIDED`, calls `signatureService.voidSubmission`, emits `agreement.voided`. Voiding a `SIGNED` agreement returns `409`.
10. **Provider swap via `SIGNATURE_PROVIDER=docuseal`** wires `DocuSealProvider` without code changes; mock default in dev/test.
11. **`docker-compose.local.yml` boots DocuSeal**: running `docker compose up` brings up DocuSeal on `:3030` alongside Postgres/Redis/RabbitMQ. Setting `SIGNATURE_PROVIDER=docuseal` in `.env` lets a developer run the full flow against real DocuSeal locally.
12. **Staging deploy config exists** under `hussle-app-dispatch-infra/` for DocuSeal container + reverse-proxy at `docuseal-staging.fleetcommand.app` + secret wiring. (Deploy execution is a separate ops step; this PR lands the config.)
13. **Coverage**: 90% line coverage on `src/shared/signatures/` and `src/agreements/` (project standard). 100% on critical paths — port contract test (any `SignatureProviderPort` impl satisfies), webhook HMAC verification, idempotency guards (webhook handler + finalize service + subscriber + watchdog republish), state-machine transitions, retry behavior.
14. **`.env.example` documents** all five new env vars with example values and prod-requirement notes.
