## Notes for /build

- **FMCSA is the gold standard.** Anything in `src/shared/signatures/` should match its FMCSA twin in file layout, naming, exports, and test structure. Diverge only where the domain genuinely differs (e.g., no caching — submissions are unique per agreement).
- **No existing HMAC webhook precedent.** Webhook verification middleware is genuinely new. Use Node's built-in `crypto.createHmac` + `crypto.timingSafeEqual`. Preserve raw request body via `express.json({ verify })` — this is the standard Express pattern.
- **DocuSeal HTTP shape** — confirm against DocuSeal v1.x API docs during /build (endpoint paths, auth header, webhook payload shape). PRD assumes the standard DocuSeal pattern; verify before implementing the adapter.
- **Idempotency is non-negotiable.** Webhook handler, `finalizeAgreement`, subscriber, and watchdog republish all hit the same Agreement row. Each path must check current status before transitioning. Tests must cover the replay case explicitly.
- **`AGREEMENT_WATCHDOG_*` env vars** are tunable. Keep defaults in `env.ts`; let tests inject smaller intervals.
- **Storage path convention** (per tech design §7.4):
  ```
  orgs/{orgId}/carriers/{carrierId}/agreements/{agreementId}/signed.pdf
  orgs/{orgId}/carriers/{carrierId}/agreements/{agreementId}/audit-certificate.pdf
  ```
  Use `src/shared/storage/index.ts` — backend (local vs S3) selected by `STORAGE_BACKEND` env var.
- **Logger redaction**: ensure `DOCUSEAL_API_KEY`, `DOCUSEAL_WEBHOOK_SECRET`, and the `X-Docuseal-Signature` header are added to the logger's redaction list before merging.
