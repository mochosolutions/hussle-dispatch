# Financial Analysis — Dispatch Fee & Driver Fee at Load Creation

> Generated by /prd-refine on 2026-03-28

## Problem

When a load is created with a carrier already assigned, `dispatchFee`, `partnerSplit` (driver fee), and `ratePerMile` are all NULL in the database. Financial calculation only runs on the separate `assignLoad` endpoint, not during `createLoad`. Additionally, the frontend hardcodes carrier rate at 80% of the customer rate instead of using the carrier's actual `dispatchFeePercent`, and the driver fee (partnerSplit) is currently calculated as a percentage of the dispatch fee rather than a percentage of total revenue.

## Solution Overview

1. Fix the `calculateLoadFinancials` formula so driver fee (partnerSplit) is based on total load revenue, not the dispatch fee.
2. Call `calculateAndPersistFinancials` during load creation when a carrier and customer rate are present.
3. Update the frontend to use the carrier's actual `dispatchFeePercent` and display a read-only "Driver Fee" field on the create load form.

## Capabilities

### Must Have (P0)

- Backend calculates and persists dispatchFee, partnerSplit, and ratePerMile at load creation time when carrierId and customerRate are both present
- partnerSplit (driver fee) is calculated as totalRevenue x partnerSplitPercent (not dispatchFee x partnerSplitPercent)
- Frontend uses the carrier's actual dispatchFeePercent when computing carrierRate (replacing hardcoded 80%)
- Read-only "Driver Fee" field visible on the create load form showing the computed partnerSplit

### Nice to Have (P1)

- None identified — this is a focused bug fix + formula correction

## User Flows

### Create Load with Carrier

1. Dispatcher opens create load form
2. Selects a carrier — form reads carrier's `dispatchFeePercent` and `partnerSplitPercent` from Redux store
3. Enters customer rate — form auto-computes carrierRate, dispatch fee preview, and driver fee preview using carrier config
4. Read-only "Driver Fee" field displays the computed amount
5. Submits the load
6. Backend creates the load AND calls `calculateAndPersistFinancials` — dispatchFee, partnerSplit, ratePerMile are persisted

### Assign Carrier After Creation

No change — the existing `assignLoad` flow already calls `calculateAndPersistFinancials`.

- `Load.ratePerMile` (Decimal 6,2) — already in schema, just not populated at creation

## Technical Context

### Existing Code to Reuse

- `calculateAndPersistFinancials` (`hussle-app-dispatch-api/src/loads/services/calculateFinancials.ts`) — already handles the full flow: sum accessorials, call `calculateLoadFinancials`, persist results. Just needs to be called from `createLoad`.
- `calculateLoadFinancials` (`hussle-app-dispatch-api/src/shared/financials.ts`) — pure function with Decimal.js precision. Formula for partnerSplit needs updating.
- `selectCarrierById` selector — already used in CreateLoadForm and DriverEconomicsSection to read carrier config from Redux store.
- `EntityAutocomplete.onSelect` callback — provides the selected option with metadata back to the parent. Can be extended to include `dispatchFeePercent` and `partnerSplitPercent`.

### Key Decisions

- **partnerSplit formula change:** `partnerSplit = totalRevenue x partnerSplitPercent` replaces `partnerSplit = dispatchFee x partnerSplitPercent`. This is a deliberate business logic change — the driver fee is their cut of the full load, not just the dispatch fee.
- **feeIncludesAccessorials toggle preserved:** The carrier-level flag that controls whether dispatch fee base includes accessorials is kept as-is.
- **No new DB columns:** All financial fields already exist on the Load model.
- **Driver fee is read-only on form:** Dispatchers cannot override the computed value. It derives from carrier config.
- **Existing tests for `calculateLoadFinancials` must be updated** to reflect the new partnerSplit formula.

## Acceptance Criteria

- When a load is created with carrierId and customerRate present, dispatchFee is persisted as a non-null value on the load record
- When a load is created with carrierId and customerRate present, partnerSplit (driver fee) is persisted as a non-null value on the load record
- partnerSplit equals (customerRate + accessorials) x carrier.partnerSplitPercent / 100 (not dispatchFee x partnerSplitPercent)
- dispatchFee equals (customerRate + accessorials) x carrier.dispatchFeePercent / 100 when carrier.feeIncludesAccessorials is true
- dispatchFee equals customerRate x carrier.dispatchFeePercent / 100 when carrier.feeIncludesAccessorials is false
- ratePerMile equals customerRate / loadedMiles when loadedMiles > 0; null otherwise
- When a carrier is selected on the create load form, carrierRate updates based on the carrier's actual dispatchFeePercent (not hardcoded 80%)
- A read-only "Driver Fee" field is visible on the create load form showing the computed partnerSplit amount
- Driver Fee updates reactively when carrier selection or customer rate changes
- Existing `assignLoad` financial calculation continues to work unchanged
- All existing `calculateLoadFinancials` unit tests are updated and pass with the new formula

## Out of Scope

- Owner-operator support (OWNER_OPERATOR carrier type remains excluded from financial calculation)
- Editable/overridable driver fee per load
- Factoring advance/reserve UI
- Invoice-level impact of formula change
- Bulk recalculation of existing loads
