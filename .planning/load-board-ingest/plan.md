# Load Board Ingest — Multi-Source Load Ingestion + Map View

> Generated by /prd-refine on 2026-04-10

## Problem

Dispatchers need to see available freight loads from multiple sources (Amazon Relay, DAT) in one place with a map showing pickup locations. Currently the Chrome extension captures Relay data but it stays trapped in the extension — no API, no UI, no map. DAT data isn't captured at all.

## Solution Overview

Build a load ingestion pipeline that accepts loads from multiple sources (Relay via extension, DAT via mock fixture), caches them in Redis using RedisJSON, and displays them on a map view in the dispatch UI. Includes Bearer token auth, server-derived org identity, and payload size limits.

## Capabilities

### Must Have (P0)
- Extension authenticates with dispatch API via Bearer token (same JWT system as dispatch UI)
- Extension auto-pushes intercepted Relay loads to the dispatch API on each refresh cycle (configurable, default 60s)
- API ingests loads from any source into Redis using RedisJSON
- API derives organizationId from JWT claims — never from request body
- API enforces payload size limits (1MB body, 100 loads max per ingest, rawData truncation)
- DAT mock: JSON fixture file loaded via a "Sync DAT" button in the dispatch UI
- Each source has its own API-side mapper normalizing data into a common `StagedLoad` shape
- Snapshot-replace on ingest: each push from a source atomically replaces all staged loads for that source+org
- Dispatch UI: Load Board page at `/loadboard` with a full-page map showing pickup location pins
- Click a pin to see load details (payout, destination, duration, equipment, stops)
- Refresh intervals are configurable (extension push interval + UI poll interval)

### Nice to Have (P1)
- Sort/filter staged loads by payout, rate per mile, equipment type, distance
- Table view toggle alongside map view
- Load count badge per source

## User Flows

### Extension Auth
1. User opens extension popup, clicks "Login"
2. Enters email + password (same credentials as dispatch UI)
3. Extension calls `POST /api/v1/auth/login` → receives access token in response body
4. Token stored in `chrome.storage.local`
5. All subsequent API calls include `Authorization: Bearer <token>`
6. On 401 → prompt re-login in popup

### Relay Ingestion (automatic)
1. Dispatcher opens `relay.amazon.com/loadboard/search` with extension active + authenticated
2. Extension intercepts `/api/loadboard/search` responses on each Relay refresh
3. Extension throttles to configured interval (default 60s) — skips pushes within the window
4. Extension POSTs raw `workOpportunities[]` to `POST /api/v1/load-board/ingest` with Bearer token
5. API extracts orgId from JWT, runs Relay mapper → normalizes to `StagedLoad` shape
6. API atomically replaces all Relay loads for the org in Redis
7. Dispatch UI auto-refreshes load board (configurable poll, default 10s)

### DAT Mock Ingestion (manual)
1. Dispatcher opens Load Board page in dispatch UI
2. Clicks "Sync DAT" button
3. UI reads bundled DAT fixture file (`datMockData.json`)
4. UI POSTs raw DAT `matchDetails[]` to `POST /api/v1/load-board/ingest`
5. API runs DAT mapper → normalizes to `StagedLoad` shape → stores in Redis
6. API replaces all previous DAT loads for the org
7. Map updates with new pins

### Map Interaction
1. Dispatcher sees full-page map with pins at pickup locations
2. Pin color indicates source (blue = Relay, orange = DAT)
3. Click pin → popup with load details: payout, rate/mile, origin → destination, duration, equipment type, stop count, pickup time
4. Dismiss popup to return to map

## Data Requirements

### Infrastructure Change
Swap Docker image from `redis:7-alpine` to `redis/redis-stack:7.4.0-v2` in `docker-compose.yml` for RedisJSON support. Same port, same persistence.

### Redis Key Structure (RedisJSON)
```
loadboard:loads:{orgId}:{source}         SET of sourceIds (TTL configurable, default 5min)
loadboard:load:{orgId}:{source}:{srcId}  JSON document per load (TTL = firstPickupTime - now, floor 5min)
loadboard:meta:{orgId}                   HASH — lastUpdated per source, total counts (TTL 5min)
```

### StagedLoad Shape (RedisJSON document)
```typescript

  source: string;            // "relay" | "dat"

  isTeamDriver: boolean;

  loadType: string | null;

  firstPickupTime: string | null;
  lastDeliveryTime: string | null;
  originCity: string | null;
  originState: string | null;
  originLat: number | null;
  originLng: number | null;
  destCity: string | null;
  destState: string | null;
  destLat: number | null;
  destLng: number | null;
  stopCount: number | null;
  costBreakdown: Record<string, number> | null;

}
```

## API/Interface Changes

### Dispatch API — New endpoints

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| `POST` | `/api/v1/load-board/ingest` | `requireAuth` | Ingest a batch of loads from any source |
| `GET` | `/api/v1/load-board/feed` | `requireAuth` | Get all staged loads for the org |
| `GET` | `/api/v1/load-board/feed/:id` | `requireAuth` | Get a single staged load detail |
| `DELETE` | `/api/v1/load-board/feed/:source` | `requireAuth` | Clear all staged loads for a source |

### Ingest Payload
```json
{
  "source": "relay",
  "loads": [ ...raw source objects (max 100)... ]
}
```

No `organizationId` in payload — derived from JWT `req.user.organizationId`.

### Ingest Validation
- Request body max: 1MB
- `loads` array max: 100 items
- `source` must be one of: `"relay"`, `"dat"`
- rawData truncated by mapper: strip nested arrays (stopRequirements, trailerDetails, actions), cap at 2KB per load

- **Auth login endpoint** (`dispatch-api/src/auth/`) — Already returns JWT. Extension popup calls this same endpoint.
- **Maps route pattern** (`dispatch-api/src/maps/routes/`) — Reference for route structure.

- **Seed data** (`dispatch-api/prisma/seed.ts`) — Dev org + user for testing.

### Key Decisions
- **Redis with RedisJSON, not Postgres** — Staged loads are ephemeral cache data replaced every 60 seconds. `redis/redis-stack` adds native JSON document support. `JSON.MGET` fetches only map-relevant fields without deserializing full objects.
- **Mappers live API-side** — Extension sends raw source data. API normalizes. Mapping bug fixes don't require extension redeployment.
- **Bearer token auth** — Extension stores JWT from login in `chrome.storage.local`, sends as `Authorization: Bearer` header. Works cross-origin (extension → localhost API). Same JWT system as dispatch UI.
- **Server-derived orgId** — Extracted from JWT claims. Never in request body. Prevents impersonation.
- **Payload size limits** — 1MB body limit, 100 loads max, rawData truncated by mapper. Prevents Redis memory exhaustion.
- **Configurable refresh** — Extension push interval (default 60s) and UI poll interval (default 10s) stored in settings.

## Acceptance Criteria

1. Extension popup shows login form; entering valid credentials stores JWT and shows "Connected" status
2. With extension authenticated and active on Relay, staged loads appear in Redis within the configured refresh interval
3. `GET /api/v1/load-board/feed` returns staged loads with correct field mapping (payout, coordinates, equipment type)
4. `GET /api/v1/load-board/feed` without valid JWT returns 401
5. Ingest payload with `organizationId` in body is ignored — org always comes from JWT
6. Ingest payload over 1MB is rejected with 413
7. Ingest payload with >100 loads is rejected with 400
8. Clicking "Sync DAT" in the UI loads fixture file and populates Redis with source="dat"
9. Each ingest replaces previous loads for that source+org (no duplicates, no stale data)
10. Load Board page renders a full-page map with one pin per staged load at its pickup lat/lng
11. Pins are color-coded by source (Relay = blue, DAT = orange)
12. Clicking a pin shows load details: payout, rate/mile, origin→destination, duration, equipment, pickup time, stop count
13. Source filter chips toggle visibility (All / Relay / DAT)
14. Map auto-refreshes on configurable interval (default 10s)
15. Extension push interval is configurable via popup setting (default 60s)
16. Extension Redux reducer replaces snapshot on each refresh (does not accumulate)
17. Loads auto-expire from Redis when their firstPickupTime passes
18. rawData in Redis does not contain nested arrays (stopRequirements, trailerDetails, etc.)
