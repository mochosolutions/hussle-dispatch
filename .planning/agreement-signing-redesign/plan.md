# Agreement Signing Redesign

> Generated by /prd-refine on 2026-05-23
> Supersedes the carrier-portal-side behavior of `document-signing` v1 (backend `src/agreements/` and `src/shared/signatures/` modules remain intact).

## Problem

The current carrier-portal agreement-signing step is a dead-end at runtime and locked to a single template:

- **Stuck on Pending.** The step renders one DocuSeal iframe and never shows a Continue button. It auto-advances only when status flips to `SIGNED`, which depends on a webhook arriving — when the webhook fails or the local DocuSeal isn't reachable, the carrier is trapped with no manual escape. Confirmed during the in-session probe: with the existing local config (mock provider returning `/dev/sign/<id>`, plus `DOCUSEAL_BASE_URL` pointing at a docker hostname not reachable from the host browser), the iframe 404s and no Continue exists.
- **Single template only.** Both the schema (`signingPhase.template = 'dispatch_v1'`) and the step component (hardcoded `TEMPLATE_KEY = 'DISPATCH_AGREEMENT'`) assume exactly one agreement. There is no path to carriers signing W-9 / Broker-Carrier Master / Factoring NOA without rewriting the step.
- **Cramped signing experience.** The iframe lives inside the standard `PortalShell` content slot, sized to ~720 px tall — adequate for desktop but cramped on mobile. DocuSeal's own signing UI assumes more vertical space than the embedded layout gives it.
- **No visibility into prefill.** The dispatch-api persists `agreement.variables` (the prefilled field values) into the DB, but the UI never displays them. Carriers can't see what's being filled into the contract until they scroll through the iframe.
- **Mock mode is unusable for end-to-end testing.** The mock provider returns an embed URL pointing at `/dev/sign/<id>`, which doesn't exist anywhere — so even though the rest of the flow works in mock mode, the signing step itself can never complete locally without flipping to real DocuSeal.

## Solution Overview

Redesign the agreement-signing step as a **focus-mode flow over a list of agreements**, schema-driven, with explicit Continue control and a dev-only mock-signing escape hatch. Backend additions are small and surgical — the bulk of the work is UI.

Three views, URL-driven, all inside the existing `PortalShell` chrome:

1. **List view** (`/sign-agreement`) — compact rows for each required agreement, status badges (signed / next / pending / blocked), and the page-level Continue button.
2. **Focus view** (`/sign-agreement/:agreementKey`) — full-viewport signing surface. Replaces the stepper with a slim `FocusHeader` + dot-trail queue indicator, replaces the footer with a `FocusFooter` whose primary action is "Sign & continue to next." DocuSeal iframe (real mode) or `MockSigningPlaceholder` (mock mode) fills the stage. Optional left rail (`AgreementPrefillSummary`) shows the values DocuSeal is prefilling.
3. **Success interstitial** (`/sign-agreement/:agreementKey/signed`) — green check + "Up next" block + 2s auto-advance to the next focus URL (or back to the list on the final agreement).

Backend changes:

- **Template registry** (`src/agreements/templates/templateRegistry.ts`) — keys → docuseal template id + `buildVariables(ctx)` function. Refactor `requestAgreement.ts` to consume it. Lands now with a single `DISPATCH_AGREEMENT` entry so adding W-9 later is a 5-line change.
- **Multi-key agreement endpoint** — change the carrier-portal agreements service so a single GET returns `Record<templateKey, AgreementContext>` for an array of requested keys, lazily creating each via `ensureAgreementForCarrier`.
- **Dev-only mock-sign endpoint** — `POST /carrier-portal/agreements/:id/mock-sign`, env-gated (404 in prod), calls `mockSignatureProvider.__testHelpers.markSigned()` and flips the Agreement row to `SIGNED`.
- **Variables surfaced to UI** — `sessionAdapters.ts` projects `agreement.variables` into the Redux session so the new `AgreementPrefillSummary` component can render them.

## Capabilities

### Must Have (P0)

#### List view
- Render a `DocumentRow` for each agreement in `selectVisibleAgreementKeys(session)`, in the order the schema declares.
- Use `state='signed' | 'next' | 'pending' | 'skipped'` from each agreement's status. `signed` rows show signedAt timestamp + View / Download links; `next` row gets a primary "Sign agreement →" button routing to `/sign-agreement/<key>`; `pending` rows are muted with a secondary "Sign now" button.
- Show `ProgressStrip` with "X of Y required signed."
- When all required agreements are `SIGNED`, render `AgreementsCompleteBanner` at the top of the list.
- When the user clicks Continue with unsigned agreements, render `AgreementsErrorBanner` at the top and scroll to the first unsigned row.
- Show `AgreementsFootNote` below the list — informational "Heads up: signing locks your business identity."

#### Focus view
- Replace `PortalShell` stepper slot with `FocusHeader` (back arrow + "All agreements" + doc title + dot-trail showing queue position).
- Replace `PortalShell` footer slot with `FocusFooter` (Cancel / Sign & continue to next).
- Main stage: `DocuSealStage` containing either the real iframe (`SIGNATURE_PROVIDER=docuseal`, status `PENDING`) or `MockSigningPlaceholder` (`SIGNATURE_PROVIDER=mock`).
- Left rail (desktop) / collapsible disclosure (mobile): `AgreementPrefillSummary` showing the values DocuSeal is filling in. Reads from `agreement.variables`.
- Polling continues every 4s while any agreement is `PENDING` (not just the focused one — handles out-of-order webhooks).
- "Sign & continue to next" button is **always enabled**, click-verifies. If status !== `SIGNED`, render inline error "Please complete signing in the document above." If `SIGNED`, navigate to `/sign-agreement/<key>/signed`.
- "Cancel" / back arrow navigates to `/sign-agreement` (list view); no state mutation.

#### Success interstitial
- Render `AgreementSignedInterstitial` with green check, signed timestamp, "Up next: <next agreement name>" block (or "All agreements signed" if final).
- Auto-advance after ~2s to the next unsigned agreement's focus URL, OR to the list view on the final agreement.
- "Back to list" secondary button always available; on final agreement it's the primary action with no auto-advance.

#### Continue button (page-level, list view only)
- Always rendered via `useStepNavigation`. Muted gray when not all signed, full primary when ready.
- Click + all signed → dispatch `submitStep({ stepId: 'sign-agreement', answers: { acknowledged: true, signedAgreementIds: [...] } })`. Cursor advances; URL ↔ cursor sync in `CarrierPortalPage` routes to the next step.
- Click + unsigned remaining → show `AgreementsErrorBanner` + scroll. No dispatch.

#### Mock-mode placeholder
- When `agreement.mock === true` (set by the backend when `SIGNATURE_PROVIDER=mock`), `AgreementFocusView` renders `MockSigningPlaceholder` inside `DocuSealStage` instead of the iframe.
- Placeholder shows a card with 🧪 emoji, copy "Mock mode — no real signing required," and a "Mark as signed" button.
- Click dispatches `markAgreementSignedMock({ agreementId })` → saga calls `POST /carrier-portal/agreements/:id/mock-sign` → backend flips status to `SIGNED` → polling sees it next tick → FocusFooter's "Sign & continue to next" becomes effective.

#### Schema + engine
- Add `TemplateEntry` to engine: `{ key: string; visibility?: Predicate }`.
- Change `Step.template?: string` to `Step.templates?: TemplateEntry[]`.
- `signingPhase.ts` declares `templates: [{ key: 'DISPATCH_AGREEMENT' }]` (single entry today; predicates available for future additions).
- New selector `selectVisibleAgreementKeys(session)` evaluates each entry's optional `visibility` against the trial session and returns ordered visible keys.

#### Redux
- Slice: replace `agreement: AgreementContext | null` with `agreements: Record<string, AgreementContext>`. Add actions `fetchAgreements({ templateKeys })`, `fetchAgreementsSuccess({ agreements })`, `markAgreementSignedMock({ agreementId })`, `markAgreementSignedMockSuccess`.
- Selectors: `selectAgreements`, `selectAgreement(key)`, `selectAllAgreementsSigned`, `selectFirstUnsignedAgreement`, `selectVisibleAgreementKeys(session)`.
- Sagas: rename `fetchAgreementSaga.ts` to handle the multi-key shape (one network call, returns the full record); add `markAgreementSignedMockSaga.ts` calling the new endpoint then re-fetching.

#### Backend — template registry
- `src/agreements/templates/templateRegistry.ts` exports `TEMPLATE_REGISTRY: Record<TemplateKey, TemplateConfig>` where `TemplateConfig = { docusealTemplateId: number; buildVariables: (ctx: BuildVariablesContext) => Record<string, string> }`.
- Lands with one entry for `DISPATCH_AGREEMENT` (variable assembly identical to the current inline code in `requestAgreement.ts:89-95`).
- `requestAgreement.ts` looks up registry entry by `input.templateKey`, calls `buildVariables(carrier)`, passes result to `signatureService.createSubmission`. No more hardcoded `DISPATCH_AGREEMENT_FIELDS` references in the service body.

#### Backend — multi-key agreements endpoint
- Change `GET /carrier-portal/agreements?templateKeys=DISPATCH_AGREEMENT,W9` to return `{ [key]: AgreementContext }`. Each missing agreement is lazily created via `ensureAgreementForCarrier`.
- Backward-compatibility for the legacy single-key form (`?templateKey=DISPATCH_AGREEMENT`) is unnecessary — only the carrier portal calls this endpoint, and it's being changed simultaneously.

#### Backend — mock-sign endpoint
- `POST /carrier-portal/agreements/:id/mock-sign`, mounted inside `carrier-portal/routes/index.ts`.
- Only registered when `env.SIGNATURE_PROVIDER === 'mock'`. Returns 404 otherwise.
- Controller invokes a new `mockSignAgreement` service that: validates the agreement belongs to the session's carrier, calls `mockSignatureProvider.__testHelpers.markSigned(agreement.providerSubmissionId)`, then updates the `Agreement` row to status `SIGNED` (same code path the production webhook handler uses, just triggered by the test helper).
- Returns the updated AgreementContext.

#### Backend — variables on AgreementContext
- `sessionAdapters.ts` projects each agreement's `variables` (already persisted on the row by `requestAgreement.ts:131`) into the `AgreementContext` the API returns. UI uses this to render `AgreementPrefillSummary`.

#### Dev preview
- Extend `SignAgreementPreview.tsx` (`/dev/onboarding-preview/sign-agreement`) with:
  - **State D** — success interstitial frame
  - **State E** — focus view with `MockSigningPlaceholder` (instead of `DocuSealStage` iframe content)
- Existing States A (overview), B (focus), C (all signed) stay as-is.

### Nice to Have (P1)

- **Refresh status link** in the focus footer (mock + real modes) — manually re-fetches agreements. Insurance against webhook-delivery failures in real mode.
- **AgreementPrefillSummary "Edit company" link** — when the prefilled value comes from a locked field, link back to Company step (which will surface a "field is locked" callout). Decide whether to ship in v1 once Company step lock UX is finalized.
- **Per-agreement "View" / "Download" actions** on signed rows — already in `DocumentRow`'s API surface; backend artifact serving may need a one-line route addition.

## User Flows

### Flow 1 — Single agreement, real DocuSeal, happy path
1. Carrier arrives at `/carrier-portal/<token>/sign-agreement`. `AgreementListView` mounts, dispatches `fetchAgreements({ templateKeys: ['DISPATCH_AGREEMENT'] })`.
2. Backend lazily ensures the envelope exists. Returns `{ DISPATCH_AGREEMENT: { status: 'PENDING', embedUrl, mock: false, variables: {...} } }`.
3. List view renders one `DocumentRow` (state `next`) + `ProgressStrip` "0 of 1 signed" + muted-gray Continue in the footer.
4. Carrier clicks "Sign agreement →". URL changes to `/sign-agreement/DISPATCH_AGREEMENT`.
5. `AgreementFocusView` mounts. `FocusHeader` shows "Agreement 1 of 1 · Dispatch Services Agreement". DocuSeal iframe loads with prefilled `carrier_legal_name`, `mc_number`, etc. Left rail shows the same values in a summary panel.
6. Carrier signs inside the iframe. DocuSeal webhook flips status. Within 4s the poll picks it up; agreement status in Redux becomes `SIGNED`.
7. Carrier clicks "Sign & continue to next". `handleSignContinue` sees `status === 'SIGNED'`, navigates to `/sign-agreement/DISPATCH_AGREEMENT/signed`.
8. `AgreementSuccessView` renders the interstitial. Since there's no next unsigned agreement, the only button is "Back to list" (primary, no auto-advance).
9. Carrier clicks. URL goes to `/sign-agreement`. List shows row as `signed` with timestamp; `AgreementsCompleteBanner` at top; Continue button transitions to full primary blue.
10. Carrier clicks Continue. `handleContinue` sees all signed, dispatches `submitStep`. Cursor advances; CarrierPortalPage routes to next step (documents-upload).

### Flow 2 — Multiple agreements, sequential
Same as Flow 1, but `templates: [{ key: 'DISPATCH_AGREEMENT' }, { key: 'BROKER_CARRIER_MASTER' }, { key: 'W9' }]`. After step 7 the success interstitial shows "Up next: Broker-Carrier Master Agreement" with a 2s auto-advance to `/sign-agreement/BROKER_CARRIER_MASTER`. Repeats for W-9. On the final success interstitial, no "Up next" — just "Back to list."

### Flow 3 — Mock mode
At step 5, instead of the iframe loading, `MockSigningPlaceholder` renders inside `DocuSealStage` (because `agreement.mock === true`). Carrier clicks "Mark as signed" — saga calls `POST /carrier-portal/agreements/:id/mock-sign`, backend flips status, polling next tick reflects `SIGNED`. From step 7 onward, identical to real mode.

### Flow 4 — Continue clicked with unsigned remaining
Carrier on list view with 1 of 3 signed clicks Continue. `handleContinue` checks `selectAllAgreementsSigned`, returns false. `AgreementsErrorBanner` renders at top: "Please sign all required agreements before continuing." Page scrolls to first unsigned row.

### Flow 5 — Cancel during focus mode
Carrier on focus view clicks Cancel or browser back. URL goes to `/sign-agreement`. List re-renders with current status. No data mutation. Polling continues in the background owned by the list view.

### Flow 6 — Refresh while in focus mode
URL is `/sign-agreement/<key>`. Page reloads. `CarrierPortalPage` reloads session, `AgreementSigningStep` mounts, sees the URL key, renders focus view. State picks back up from Redux + fresh fetch.

### Flow 7 — Webhook never arrives (real mode)
After signing in the iframe, the carrier never sees status flip to `SIGNED`. Polling keeps returning `PENDING`. Clicking "Sign & continue to next" surfaces the inline error indefinitely. **Workaround in P0:** the carrier or dispatcher must investigate the webhook plumbing. **P1 mitigation:** "Refresh status" link in the focus footer.

### Flow 8 — Agreement reaches a terminal failure state
`VOIDED` / `DECLINED` / `EXPIRED` are projected into `DocumentRow` as a red-bordered "blocked" variant with helper copy "Contact your dispatcher." Continue still errors if clicked — blocked agreements are treated identically to unsigned for completion purposes.

## Technical Context

### Existing Code to Reuse

- **`PortalShell`** (`features/carrier-portal/components/PortalShell/index.tsx`) — main chrome. Accepts `stepper` and `footer` slots; we'll pass `FocusHeader` and `FocusFooter` for focus-mode views.
- **`FocusHeader`, `FocusFooter`, `DocuSealStage`, `DotTrail`** — already exist in `features/carrier-portal/components/`. Built for an earlier focus-mode design that became the v1 SignAgreementPreview; production hasn't used them yet. We adopt them as-is.
- **`OnboardingCard`, `ProgressStrip`, `DocumentRow`, `Callout`** — list-view primitives; already in production use.
- **`useStepNavigation`** (`features/carrier-portal/components/StepNavContext/`) — page-level Continue handler registry. `AgreementListView` calls this with `onContinue` that verifies all signed before dispatching `submitStep`.
- **`submitStep` action + saga** — reused unchanged. Step component dispatches `submitStep({ stepId: 'sign-agreement', answers: { acknowledged: true, signedAgreementIds: [...] } })`; cursor advance + URL sync happens via existing `CarrierPortalPage` plumbing.
- **`ensureAgreementForCarrier`** (`hussle-app-dispatch-api/src/agreements/services/`) — already does the lazy-create. The multi-key endpoint just calls it in a loop.
- **`mockSignatureProvider.__testHelpers.markSigned`** (`hussle-app-dispatch-api/src/shared/signatures/mockSignatureProvider.ts:151`) — the new mock-sign service composes this with a `Agreement` row status flip (mirroring what the production webhook handler does).
- **`probe:docuseal-prefill` script** (`hussle-app-dispatch-api/scripts/probe-docuseal-prefill.ts`) — built during this conversation. Used during /build to confirm a fresh DocuSeal template's prefill works end-to-end without touching production code paths.

### Key Decisions

- **Focus-mode flow over inline iframe cards.** Designer mockup at `docs/screenshots/mockups/onboarding/Sign Agreement Focus.html` validates: list = home base, focus = full-viewport signing, success = interstitial. The iframe needs the room.
- **URL-driven view selection** (not internal component state). Bookmarkable, browser-back works, refresh-while-signing keeps the user on the right view.
- **Continue always rendered, click-verifies.** Single mental model for the user — the button exists, clicking it either advances or tells you what's missing.
- **Step-level auto-advance removed; in-step auto-advance kept.** The original auto-advance-on-SIGNED behavior was the source of "stuck on Pending" UX. The 2s success interstitial → next focus auto-advance is pacing within the agreement queue, not step navigation.
- **Schema-driven template list** (Option A from prior discussion). Keeps the schema-as-data property — swap `carrierSchema.ts` for `driverSchema.ts` to get a different domain's onboarding without touching backend. Predicates on individual `TemplateEntry` entries cover the reactivity case (`{ key: 'INSURANCE_RIDER', visibility: { path: 'equipment.types', includes: 'REEFER' } }`).
- **Template registry lands now with one entry.** Refactoring `requestAgreement.ts` to consume the registry — even with a single key today — locks in the shape so adding W-9 / Broker / NOA is purely additive.
- **Mock-sign endpoint, not a fake `/dev/sign` UI.** The mock provider's `__testHelpers.markSigned` is the cleanest leverage point. Surfacing it via a dev-only endpoint keeps the production code path (`POST /agreements/:id/mock-sign` → flip row → poll detects) identical in shape to the real path (DocuSeal webhook → flip row → poll detects).
- **`AgreementPrefillSummary` included in v1**, not deferred. Backend already persists `variables`; surfacing them is a small UI component. Better mobile UX, gives the carrier a clean summary of what's being filled in.
- **`Carrier` vs `First Party` role discrepancy** (runbook says one, code defaults to the other, test assertion conflicts) — out of scope for this plan but worth fixing in a small drive-by. Recommend updating runbook to `First Party` (matches code default + the local template we built during this session).

### What's NOT changing

- The `Agreement` Prisma model
- The `src/shared/signatures/` provider port + DocuSeal/mock adapter implementations
- The webhook handler at `/webhooks/docuseal`
- The watchdog cron (`AGREEMENT_WATCHDOG_INTERVAL_MIN`)
- The `submitStep` saga, the cursor advance, the URL ↔ cursor sync in `CarrierPortalPage`
- The signed PDF artifact pipeline (S3 upload, audit certificate)
