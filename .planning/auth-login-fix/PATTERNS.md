## Notes for /build

- **Grace window implementation** (the trickiest piece): in `rotateSessionRedis.ts`, after writing the new session/refresh/index keys (lines 96-98 today), replace the existing `redisClient.del(refreshTokenKey)` at line 75 with `redisClient.set(refreshTokenKey, newSessionKey, 'EX', 10)`. The OLD token now points to the NEW session for 10 seconds, then expires naturally. **Keep** the `redisClient.del(sessionKey)` and `redisClient.del('session:index:...')` calls — only the refresh-token-key gets the grace treatment.
- **Cookie maxAge change must be applied at every `setRefreshTokenCookie` callsite** (6 controllers — login, refreshToken, passwordChallenge, signupOrg, switchOrg, acceptInvite). Centralize by making the function read maxAge from a single helper or from the session object. The cleanest approach: pass `rememberMe` (or computed `maxAgeMs`) explicitly at each site.
- **`refreshScheduler` lifecycle**: schedule on login success, login bootstrap (`/auth/me`), and every successful refresh. Cancel on logout. Singleton module state is fine — there's only one auth session per tab.
- **Retry policy in axios.ts**: use `error.response === undefined` as the "transient" signal (axios sets this only when there's no HTTP response). Do not retry if `error.response.status` exists.
