## Representative Patterns

### Content-script entry pattern
_Source: `src/contentScript/index.ts` (typical MV3 content script)_

Reads page DOM, posts messages to background worker via `chrome.runtime.sendMessage`. Background worker handles auth + relays to API. Do NOT call API directly from content scripts (CORS + extension ID validation).

### Popup pattern
_Source: `src/popup/index.tsx`_

Standard React + Redux Toolkit popup. `<Provider>` wraps the popup; sagas + thunks both wired. Sagas handle long-running auth flows; thunks handle simple fire-and-forget actions.

### Site-specific scraper
_Source: `src/sites/dat/*` and `src/sites/relay/*`_

Per-site module exports `extract(): Load[]` and `subscribe(callback)`. The content script picks the site module based on `window.location.hostname`.

## Conventions to follow

- New scrapers: add a site module under `src/sites/<site>/`, register in `manifest.json` `content_scripts`.
- Message passing: use `chrome.runtime.sendMessage` from content → background. Background → popup uses Redux store sync (chrome.storage-backed).
- TypeScript 4.8 here — modern TS features (e.g., `satisfies`) may not be available. Match existing style.
- Never bundle secrets into the extension — fetch credentials from background-worker → backend.
