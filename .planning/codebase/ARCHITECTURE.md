## Data Flow

### Primary write path (UI → API → DB → events)

```
Browser (React)
  → Axios HTTP (cookie-auth JWT)
  → Express route (security middleware: helmet, cors, rate-limit, cookie-parser)
  → requireAuth / requireRole / requireAuthOrInviteToken
  → Yup validator (validateRequest middleware)
  → controller (calls pre-wired service from compositionRoot)
  → service (depends on port interfaces — never Prisma directly)
  → repository (Prisma) → Postgres
  → service returns { data, events }
  → controller dispatches events via eventDispatcher.dispatchAll(events)
  → events publish to RabbitMQ → subscribers in same Node process
  → controller transforms data → JSON response
  → Axios interceptor → saga handler → Redux entity/page slice updates
  → React re-renders
```

### Auth flow

- **Portals:** invite-token via `requireAuthOrInviteToken` (`src/shared/middleware/requireAuthOrInviteToken.ts`).

## Key Patterns

- **Hexagonal modules (API):** controllers → services → ports → repositories. Per-module `compositionRoot.ts` wires the graph with shared deps (`prisma`, `eventBus`, `logger`). Cross-module communication via typed RabbitMQ event bus, never direct service-to-service imports.
- **`ServiceResult<T>` envelope:** services return `Promise<{ data: T; events: DomainEvent[] }>` — controllers dispatch the events.
- **Money safety:** Decimal fields use `decimal.js`; API JSON serializer registers `decimalReplacer` so Decimals serialize as strings (preventing precision loss). UI must treat money as strings.
- **Dual-slice Redux:** entity + page slices per feature, factories at `hussle-app-dispatch-ui/src/utils/redux/`.
- **MUI v5 only:** no styled-components, no Tailwind, no second component lib. `sx` prop for styling.
- **No `any` / `as` / `!`:** strict TS in API (errors), warnings in UI (migration override). `noUncheckedIndexedAccess: true` in API.
- **Form-field discriminated union:** `DynamicForm` + question schema typed by `inputType` discriminator.

## Architectural Constraints

- Single Node event loop on API; long work via RabbitMQ subscribers in same process today.
- Three intentional singletons: `prisma`, `redisClient`, `sharedEventBus`. Everything else injected through composition roots.
- Auth tokens NEVER in Redux state or `localStorage` — HttpOnly cookies only.
- `dependency-cruiser` enforces: services may not import `@prisma/client`, services may not import repositories directly, services may not import controllers, no circular deps.
- Routes don't reach Prisma — they receive pre-wired controllers from `compositionRoot.ts`.

## Cross-Cutting Concerns

- **Logging:** `LoggerPort` injected through composition roots. Never `console.log`.
- **Errors:** typed `CustomError` hierarchy (`BadRequestError`, `NotFoundError`, `ConflictError`, `UnauthorizedError`, `ForbiddenError`, `RequestValidationError`, `GoneError`, `MissingEnvError`). Centralized handler at `src/shared/middleware/errorHandler.ts` serializes to `{ errors: [...] }`. UI catches via Axios interceptor → saga try/catch → `notistack` toast.
- **Validation:** format = Yup schema (middleware), business rules = inside service functions.
- **Multi-tenant scoping:** every list/read query passes `organizationId` (sometimes `managedByOrgId` for carriers) through mapper → service → repository. Soft-delete via `deletedAt: null`.
