# Track 10 — Chrome Extension (DAT/Relay)

> Generated by /prd-refine on 2026-04-26
> Source: `docs/tasks/mvp-plan.md` Track 10
> Related planning: `.planning/load-board-ingest/`, `.planning/load-board-prod/`

## Context

Track 10 ships the Chrome extension that scrapes load board pages (DAT + Amazon Relay), pushes them to `POST /api/v1/load-board/ingest`, and surfaces them in the dispatcher feed. Audit revealed two **hard blockers** the original task list missed:

1. **The extension is broken today.** It POSTs to `/load-board/ingest` without an `Authorization` header, but the route requires `appAuth` middleware. Every request 401s. Nobody has caught this because nobody is using it on staging yet.
2. **Two background files diverged.** `background.ts` (TypeScript source, never bundled) and `background.js` (active hand-edited file). New Track 10 work would have to choose one or the other; we choose TS.

Several other items in the original mvp-plan list are stale:
- `PUSH_DAT_LOADS` handler **already exists** (`background.js:81-88`) — not new work.
- `cheerio` and `ioredis` are **not** in `package.json` — that bullet is stale. Only `yup` and `ts-node` are unused.
- The actual extension lives at `dat-load-scraper/`, not `extension/` as `packages.json` claims.

This plan therefore reframes Track 10 as: **make the extension actually work end-to-end on staging**, with the original tasks layered on top.

## Refined Scope (from /prd-refine 2026-04-26)

| Question | Decision |
|---|---|
| Extension auth | **Long-lived per-org API key.** User pastes once into popup; backend adds `apiKeyAuth` middleware variant on `/load-board/ingest`. No session refresh. |
| API URL config | **Build-time env var only.** Webpack `DefinePlugin` substitutes `process.env.API_URL` at build. Separate `extension-staging.zip` / `extension-prod.zip`. |
| Backend dedup | **Per-record skip + count in response.** For each load, check `(orgId, source, sourceId)` in Redis. Skip if exists. Response: `{ ingested, skipped }`. No errors. |
| Failed-ingest retry | **No queue.** Surface error count via badge + popup; manual user retry. (MVP simplicity over robustness.) |
| Background file | **Consolidate to TS, drop JS.** Delete `background.js`; webpack bundles `background.ts` to `dist/background.js`. Single source of truth. |
| Validator strictness | **Min-required fields per source.** Reject obvious garbage; allow extra fields so DAT/Relay API drift doesn't break ingest. |

## Solution Overview

### Backend (`hussle-app-dispatch-api/`)

#### 10.BE.0 _(NEW — unblocks everything)_ — Per-org API key + apiKeyAuth middleware

- **Prisma model** `OrgApiKey`:
  - `id` (uuid PK)
  - `organizationId` (FK)
  - `name` (string, e.g. "Chrome extension – john's laptop")
  - `keyHash` (string, sha256 of full key — never store plaintext)
  - `keyPrefix` (string, first 12 chars `fc_live_xxxx` for display in UI listing)
  - `lastUsedAt` (DateTime?)
  - `revokedAt` (DateTime?)
  - `createdAt` / `updatedAt`
  - Index `(keyPrefix)` for fast lookup
- **Migration** `20260427000000_add_org_api_key`.
- **Service** `apiKeyService.ts`:
  - `generate({ organizationId, name })` → returns `{ key, record }`. Key format `fc_live_<24url-safe-chars>`. Hash with sha256, store hash + prefix only. Plaintext key is shown **once** in the response and never recoverable.
  - `verify(key)` → loads by prefix, hashes input, constant-time compares, returns `{ organizationId }` or null. Updates `lastUsedAt` async (no blocking).
  - `revoke(id)` → sets `revokedAt`.
  - `listForOrg(organizationId)` → list all keys (prefix only, never full).
- **Middleware** `shared/middleware/apiKeyAuth.ts`:
  - Parses `Authorization: Bearer <key>`.
  - On valid key, sets `req.organizationId` (matching `appAuth` semantics) and a marker `req.authMethod = 'apiKey'`.
  - On invalid/missing/revoked → 401.
- **Composite middleware** `shared/middleware/sessionOrApiKeyAuth.ts`:
  - Tries `apiKeyAuth` first if Authorization header looks like `Bearer fc_live_…`; otherwise falls back to `appAuth` (session/JWT). Lets the same route accept both auth styles.
- **Apply** to `POST /load-board/ingest` only (do not broaden surface).

#### 10.BE.1 — Strict validator on `/load-board/ingest`

Replace `yup.mixed()` per-load with discriminated schemas. **Min-required fields per source:**

```typescript
// load-board/validators/ingestValidator.ts
const datLoadSchema = yup.object({
  matchId: yup.string().required(),
  origin: yup.object({
    city: yup.string().nullable(),
    state: yup.string().required(),
  }).required(),
  destination: yup.object({
    city: yup.string().nullable(),
    state: yup.string().required(),
  }).required(),
  equipmentTypeCode: yup.string().nullable(),
}).unknown(true);  // allow upstream API drift

const relayLoadSchema = yup.object({
  id: yup.string().required(),
  startLocation: yup.object({
    city: yup.string().nullable(),
    state: yup.string().required(),
  }).required(),
  endLocation: yup.object({
    city: yup.string().nullable(),
    state: yup.string().required(),
  }).required(),
  loads: yup.array().of(yup.object().unknown(true)).min(1),
}).unknown(true);

export const ingestValidator = yup.object({
  body: yup.object({
    source: yup.string().oneOf(['relay', 'dat']).required(),
    loads: yup.array()
      .max(100)
      .when('source', {
        is: 'dat',
        then: (s) => s.of(datLoadSchema).required(),
        otherwise: (s) => s.of(relayLoadSchema).required(),
      }),
  }),
});
```

#### 10.BE.2 — Per-record dedup + count response

Update `loadBoardService.ingest`:
- Replace `snapshotReplace` with new flow:
  1. For each mapped load, check `redis.exists(loadboard:load:<orgId>:<source>:<sourceId>)`.
  2. If exists → push to `skipped[]`, **do not overwrite**.
  3. If new → write to Redis (existing key shape + TTL logic untouched) + add to set member list.
- Return `{ ingested: number, skipped: number, total: number }` (renames the old `count`).
- Update `loadBoardRedisAdapter` API: split `snapshotReplace` into `addIfAbsent(load)` (returns boolean). Or keep `snapshotReplace` and add a new `addIfAbsent` method side-by-side; mark old one deprecated.
- Update `relayMapper.test.ts` / `datMapper.test.ts` and add new `loadBoardService.dedup.test.ts`.

### Extension (`dat-load-scraper/`)

#### 10.EXT.0 _(NEW — unblocks everything)_ — Send Authorization header

- Add `apiKey` field to `chrome.storage.local` schema.
- `pushLoadsToApi()` reads it and sets `Authorization: Bearer <apiKey>` on every POST.
- On 401 response: clear stored key + show popup error "API key invalid — paste a new one".
- Block the message handler entirely if no key is stored — surface "Set API key in extension popup" toast.

#### 10.EXT.0b _(NEW)_ — Popup: API key entry

- Popup adds a "Settings" view with a single password-style text field: "FleetCommand API Key".
- Save button persists to `chrome.storage.local`. Show last 4 chars + "Connected to: <orgName>" if a verification ping succeeds.
- Optional verification call: `GET /load-board/ping` (new lightweight route under `apiKeyAuth`). Returns `{ organizationId, organizationName }`.

#### 10.EXT.1 _(verify-only)_ — DAT push handler

- Already exists at `background.js:81-88`. After 10.EXT.6 consolidation, ensure the TS version mirrors the JS handler. Add unit test (covered by 10.EXT.5).

#### 10.EXT.2 — Build-time API URL

- `webpack.common.js`: `new DefinePlugin({ 'process.env.API_URL': JSON.stringify(process.env.API_URL || 'http://localhost:3001') })`.
- Replace hardcoded `http://localhost:3001/...` strings with `${process.env.API_URL}/api/v1/load-board/ingest`.
- `package.json` scripts:
  - `build:local` → no env (defaults to localhost:3001)
  - `build:staging` → `API_URL=https://api-staging.fleetcommand.app`
  - `build:prod` → `API_URL=https://api.fleetcommand.app`
- Drop hardcoded `localhost:3001` from `manifest.json` `host_permissions` — replace with `https://*.fleetcommand.app/*` plus `http://localhost:3001/*` (kept for dev). Build-time env var also rewrites manifest if needed (use a small build-time script).

#### 10.EXT.3 — Surface ingest errors to user (no retry queue)

- On any ingest failure (network, 4xx, 5xx): increment a `failedCount` in `chrome.storage.local`.
- Set badge text = `failedCount` with red background when > 0.
- Popup shows a "Last error: <timestamp> — <message>" row with a "Retry now" button (re-runs the most recent failed payload, kept in storage as `lastFailedPayload`).
- Successful ingest clears badge + clears `lastFailedPayload`.

#### 10.EXT.4 — Remove unused deps

- Drop `yup` from `dat-load-scraper/package.json` (unused in extension code).
- Drop `ts-node` (no script invokes it).
- Run `npm prune` and commit updated `package-lock.json`.
- (Per audit, `cheerio` and `ioredis` are NOT present — original mvp-plan bullet was stale. Update mvp-plan footer.)

#### 10.EXT.5 — Test coverage

- `package.json` `test` script: `jest`.

#### 10.EXT.6 _(NEW)_ — Consolidate background.ts; delete background.js

## Acceptance Criteria

1. `OrgApiKey` table exists with hashed-key storage; plaintext keys are never persisted.
2. `apiKeyService.generate` returns the plaintext key exactly once; subsequent reads expose only `keyPrefix`.
3. `POST /api/v1/load-board/ingest` accepts `Authorization: Bearer fc_live_…` and rejects missing/invalid/revoked keys with 401.
4. `POST /api/v1/load-board/ingest` rejects payloads where any DAT load lacks `matchId`, origin/destination state, with 400.
5. `POST /api/v1/load-board/ingest` rejects payloads where any Relay load lacks `id`, start/end state, or has empty `loads[]`, with 400.
6. Same-payload re-POST returns `{ ingested: 0, skipped: N }`. New + duplicate mix returns split counts.
7. Built extension's `manifest.json` and bundled JS reference the API URL from `process.env.API_URL` at build time; no `localhost` strings in the prod build.
8. Extension popup has a single API-key input field; save persists to `chrome.storage.local`; verification ping shows org name on success.
9. Every ingest POST from the extension includes `Authorization: Bearer <storedKey>`.
10. Failed ingest sets badge text to failure count + red background; popup surfaces last error + Retry button; success clears badge.
11. `dat-load-scraper/package.json` no longer lists `yup` or `ts-node`.
12. `dat-load-scraper/src/contentScript/background.js` is deleted; `background.ts` is the only source.
13. Jest test suite in `dat-load-scraper` runs and passes for: `pushLoadsToApi`, `removeDuplicates`, `relayMapper`, `datHandler`, `messageRouting`.
14. `cd hussle-app-dispatch-api && npm run validate` passes (no new failures).
15. Manual verification (10.V.1) walked through end-to-end on local dev with screenshots in `e2e-results/track-10/`.
