## Problem

FleetCommand's loads feature is the visible "gold standard" — every other entity page looks half-finished by comparison. A static audit plus a live Playwright walkthrough across every reachable route surfaced concrete defects that will cause new users to abandon the app on first contact:

- **Initial-load flicker** on `/carriers`, `/drivers`, `/vehicles`, `/customers`, `/contacts`, `/places` — KPI tiles flash `0` then jump to real values, grids resize when data arrives, `PageWrapper isLoading` unmounts and remounts children.
- **Documents drawer renders raw S3 `AccessDenied` XML** when a presigned-URL fetch 403s — no skeleton, no fallback, no friendly error. (Reproduced live.)
- **Document table** missing `Uploaded By` / `Size` / file-type icon columns; uses unbounded `autoHeight` instead of pagination.
- **`KpiCell` + `LinkText` produce `<p>` inside `<p>`** — DOM nesting violation logged on every Contact detail page load.
- **Customer detail summary bar** stacks fields vertically instead of the 4-column grid every other entity uses.
- **Contact detail "Customer" field** displays the raw UUID instead of resolving to the company name.
- **Driver license expiry** rendered as raw ISO `2030-07-14T00:00:00.000Z`.
- **187 files import raw `Typography` from `@mui/material`** despite a 22-component named typography library at `src/components/Typography/index.tsx` being available — variants are mixed inconsistently for the same semantic role.
- **Accounting and invoices** features are fully built but commented out in routes and navigation; the user can't access them.
- Cross-cutting visual stragglers: MUI Switch off-track is `secondary` (reads as alert); body/meta sizes are visually small; toasts position is inconsistent.

The user explicitly framed the brief: "Find all of the potential issues so that users do not abandon the app after using it due to UX issues." This pass closes those gaps.

## Solution Overview

A coordinated polish pass split across **13 tracks (A–N)** delivered as **one PR per track** (per D.1). Each track aligns one slice of the app to the loads-feature pattern, fixes the live bugs found in that slice, and ships its own snapshot/test updates.

The scope spans:

1. **Eliminate list-page flicker** by changing slice `initialState.loading.getAll = true`, adding a `hasLoadedOnce` flag, and a stale-while-revalidate guard (Track A). Drops `mountedRef`; replaces it with a self-documenting Redux state.
2. **Detail-page alignment** — remove `PageWrapper isLoading` everywhere, normalize KPI bars, fix per-entity bugs (Track B).
3. **Drawer + modal verification** — confirm the existing `FormDrawer` dirty-form blocker fires on every drawer (live audit showed it already works on the wrappers); migrate two stragglers to the Redux modal registry (Track C).
4. **Form schema TS errors** that will misbehave at runtime (Track D).
5. **`SectionCard` adoption** in 9 detail-page tabs that use raw `Card` / `MainCard`, gated on a one-paragraph rule codified in `CLAUDE.md` (Track E).
6. **Typography migration** off raw `<Typography>` onto the 22 named components, using `/component-library` as the variant→component cheat sheet (Track F).
7. **Documents refactor finish** — restore loading/error states, add columns, add MIME/size validation, paired with an infra IAM fix for the underlying 403 (Track G + D.6).
8. **List-page small-fries** — empty state variants, FilterBar padding, `PageWrapper isLoading={false}` removal (Track H).
9. **Cross-cutting visual polish** — Switch off-mode color, +3px global typography bump, toast bottom-right (Track I + D.5).
10. **Non-visible refactors** — Driver `searchQueryRef` → Redux, Vehicle subscription-check pre-fetch, KPI accuracy by active filter (Track J).
11. **Live bugs** caught during the Playwright walkthrough — 11 concrete defects (Track K).
12. **Settings page** alignment (lighter L.a fix per D.7) (Track L).
13. **Invoices + Accounting turn-on** — uncomment routes and nav, polish each page through Tracks A/B/E/F/I (Track N for invoices, Track M for accounting; N before M per D.8).

## User Flows

This is a **non-functional polish pass** — no new user-facing features. The user-visible bar is "no regressions, no flicker, no dropped edits." Specific flows verified during the pass:

### List → Detail navigation (per entity)
1. User logs in, lands on Dashboard.
2. Clicks a sidebar nav item (e.g. Carriers).
3. List page renders with KPI skeletons and a fixed-height grid container immediately. No `0`-flash. No layout shift.
4. Once data arrives, grid populates and KPI tiles fade in to real values.
5. User clicks a row.
6. Detail page renders without a full-page reload of the layout (no `PageWrapper isLoading` unmount). Content fills in; tab content lazy-loads on first switch with a per-tab loading indicator.

### Drawer edit + dirty-form guard
1. User opens any edit drawer.
2. Modifies a field.
3. Attempts to close (X button).
4. "Discard unsaved changes?" dialog appears with Keep Editing / Discard.
5. Discard closes the drawer; Keep Editing keeps it open with state intact.

### Document preview
1. User clicks a document row in any detail-page Documents tab.
2. Detail drawer opens.
3. Preview area shows skeleton.
4. On success: PDF or image loads inline.
5. On 403 / network error: "Preview unavailable — Download instead" with a Download CTA.

### Invoice send (Track N)
1. User opens a delivered load, navigates to Documents → Send Invoice.
2. SendInvoiceModal opens (Redux-registered).
3. Customer email pre-filled. CC chips field shows contact's `ccEmails` as defaults; user can add/remove.
4. Submit → invoice marked SENT, customer email fires.

### Carrier FACTORED dispatch-fee invoice (Track N.5)
1. EXTERNAL_CARRIER load delivered. Carrier `billingMethod = FACTORED`.
2. Auto-generated `DISPATCH_FEE` invoice created with status `DRAFT`.
3. **No** auto-email sent. (Mirror of customer-side FACTORED behavior.)
4. User reviews from invoice list, manually sends.

## Data Requirements

**Local Redux slice shape changes (dispatch-ui only — Track A.1, A.2, A.3):**

For each entity slice (`carrier`, `driver`, `vehicle`, `customer`, `contact`, `place`, `invoice`, `settlement`, ...):

```ts
interface PageSliceState {
  // existing fields...
  loading: {
    getAll: boolean; // CHANGED: initialState now `true` instead of `false`/undefined
    // ...
  };
  hasLoadedOnce: boolean; // NEW — flips to true on first successful fetch
  lastFetchedAt: number | null; // NEW — epoch ms; drives stale-while-revalidate
}
```

Plus a new shared util:

```ts
// src/utils/redux/staleness.ts
export const STALE_TTL_MS = 60_000;
export const isStale = (lastFetchedAt: number | null, ttl = STALE_TTL_MS): boolean =>
  !lastFetchedAt || Date.now() - lastFetchedAt > ttl;
```

### Key Decisions

| # | Decision | Why |
|---|---|---|
| D.1 | One PR per track (A–N). ~13 PRs total. | Easier review, easier revert, decouples track failures. |
