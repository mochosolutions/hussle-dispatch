# Track 7 — Driver Management (Cleanup)

> Generated by /prd-refine on 2026-04-23

## Problem

Most of Track 7 is already implemented — driver CRUD, pay config UI, location drawer, availability schedule endpoints + UI all exist. Three small gaps remain: (1) the backend driver validator doesn't validate `payType`/`payRate`, allowing invalid values through, (2) the location drawer saves city/state but doesn't geocode to lat/lng coordinates, breaking deadhead distance calculations, and (3) the carrier portal driver validator excludes `PER_HOUR` from allowed pay types despite the schema and financials code supporting it.

## Solution Overview

Three targeted fixes to close the gaps in the existing driver management system. No new pages, no new models, no new endpoints.

## Capabilities

### Must Have (P0)
- Backend driver validator enforces valid `payType` enum values (PERCENTAGE, PER_MILE, PER_HOUR, FLAT_RATE) and requires `payRate` when `payType` is set
- Location update geocodes city/state to lat/lng via AWS Location Service (already integrated)
- Carrier portal validator accepts all 4 pay types

## User Flows

### Flow 1: Driver Pay Config
1. Dispatcher opens driver detail → clicks edit on driver info
2. `DriverFormDrawer` shows pay type selector (4 options) + pay rate input
3. On save → `PATCH /drivers/:id` with `payType` + `payRate`
4. Backend validates `payType` is one of the 4 enum values, `payRate` required when `payType` set
5. Load financial calculations use driver pay config for `driverPay` field

### Flow 2: Driver Location Update
1. Dispatcher opens driver detail → clicks edit location
2. `DriverLocationDrawer` shows current city/state + home base + availability
3. On save → `PATCH /drivers/:id` with `currentCity` + `currentState`
4. Backend detects city/state changed → geocodes via AWS Location Service → sets `currentLatitude`/`currentLongitude`
5. Deadhead distance calculations now use accurate coordinates

## Data Requirements

No schema changes. All fields already exist:
- `Driver.payType` (DriverPayType enum: PERCENTAGE, PER_MILE, PER_HOUR, FLAT_RATE)
- `Driver.payRate` (Decimal 7,4)
- `Driver.currentCity`, `Driver.currentState` (String?)
- `Driver.currentLatitude`, `Driver.currentLongitude` (Decimal 9,6)

## API/Interface Changes

No new endpoints. Existing `PATCH /drivers/:id` gains:
- `payType` validation (enum check)
- `payRate` validation (required when payType set, min 0)
- Auto-geocoding when `currentCity`/`currentState` change

## Affected Services

| Service | Changes |
|---------|---------|
| dispatch-api | Driver validator (add payType/payRate rules), driver service (geocode on location update), carrier portal validator (add PER_HOUR) |

## Technical Context

### Existing Code to Reuse
- `shared/geoLookup.ts` (`dispatch-api`) — geocoding utility, already wraps AWS Location Service
- `shared/providers/awsLocationProvider.ts` (`dispatch-api`) — AWS Location Service provider with typeahead, routing, geocoding
- `checkCarrierOnboarding` pattern — example of service calling a shared utility during update
- `driverValidators.ts` (`dispatch-api`) — existing create/update validators, just missing payType/payRate fields
- `carrier-portal/validators/driversValidator.ts` — has `PAY_TYPES` array missing `PER_HOUR`

### Key Decisions
- **Geocoding is best-effort** — if AWS Location Service is unavailable or city/state doesn't resolve, log a warning and proceed. Don't block the update.
- **Geocode only on change** — only call the geocoder when `currentCity` or `currentState` actually changed from the existing values. Don't re-geocode on every update.
- **No UI changes needed** — all 3 fixes are backend-only. The driver form, location drawer, and detail page already work correctly.

## Acceptance Criteria

### Pay Type Validation
- [ ] `PATCH /drivers/:id` with `payType: 'INVALID'` returns 400 validation error
- [ ] `PATCH /drivers/:id` with `payType: 'FLAT_RATE'` and no `payRate` returns 400
- [ ] `PATCH /drivers/:id` with `payType: 'PER_MILE'` and `payRate: 0.55` succeeds
- [ ] `PATCH /drivers/:id` with `payType: null` and `payRate: null` succeeds (clearing pay config)
- [ ] All 4 pay types accepted: PERCENTAGE, PER_MILE, PER_HOUR, FLAT_RATE

### Location Geocoding
- [ ] Updating `currentCity`/`currentState` auto-populates `currentLatitude`/`currentLongitude`
- [ ] Geocoding failure doesn't block the update (warning logged, city/state still saved)
- [ ] Updating only unrelated fields (e.g., `notes`) does not trigger geocoding
- [ ] Clearing city/state clears coordinates too

### Carrier Portal Validator
- [ ] Carrier portal accepts `PER_HOUR` as a valid pay type (alongside PERCENTAGE, PER_MILE, FLAT_RATE)
